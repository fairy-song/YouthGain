# 财务推荐 v2 工程定义

## 1. 数据库建表 SQL

```text
backend/app/sql/podcast_recommendations.sql
  daily_picks: PRIMARY KEY(user_id, local_date)，固定当天推荐（空状态也缓存）
  finance_snapshots: snapshot_id，禁止 UPDATE/DELETE，完整冻结特征和缺失掩码
  recommendation_events: PRIMARY KEY(user_id, event_id)，禁止 UPDATE/DELETE
  served 每条推荐唯一；impression/click/反馈按不同事件 ID 全部追加；重试复用 ID

backend/app/sql/finance_funds.sql
  finance_goal_migrations: 每用户首次旧目标迁移记录
  finance_goals: 当前目标投影，与以下追加记录在同一个 SQLite 事务提交
  finance_goal_versions: 目标历史版本，按 recorded_at/revision 读取时点状态
  savings_transfers: 内部划拨 signed locked_delta_cents（正=锁定，负=释放）
  monthly_carryovers: 月初日常结转确认，追加修正，禁止修改旧确认
```

```sql
-- 旧 daily_picks 库由 podcast_store 在串行迁移时判断列是否存在再执行：
ALTER TABLE daily_picks ADD COLUMN recommendation_id TEXT;
CREATE UNIQUE INDEX IF NOT EXISTS daily_picks_recommendation_id
  ON daily_picks(recommendation_id) WHERE recommendation_id IS NOT NULL;
```

```python
# 经用户确认的资金公式，全部先用分计算：
available_remaining_month = carryover_month + actual_income_month - net_expense_month - savings_net_transfer_month
# savings_locked_total 独立特征；不能再从上式扣一次锁定总额。
# 上月结转本身已排除以前的锁定资金。缺少结转确认时结果为 None。
# 存入目标：locked_delta > 0；释放/取消/删除目标：locked_delta < 0。
# 内部划拨不新增 expense/income，不参与支出图表和实际收入统计。
# 跨月：沿最近的已确认结转，滚动已记录实际收支与对应月份的内部划拨。
```

```text
旧目标迁移：已存金额成为初始锁定余额，不产生“本月新划拨”；用户确认日常结转时排除这些旧锁定资金。
结束目标：释放锁定资金；真正付款仍须单独记支出，不能把“结束目标”按钮当作记账。
目标规划：传给 goal_planner 的 balance = 日常可用剩余 + 锁定总额；规划器只扣一次目标锁定资金。
规划特征：goal_plan_shortfall / planned_free_now，缺少必要开支、缓冲或收入排期时标记未知。
```

```python
# 推荐编排（实际实现见 podcast_service.py）：
# 1. 确定用户时区与当地日期；读取同日缓存，若存在立即返回。
# 2. 短事务读取候选、历史事件、拒绝状态后关闭连接。
# 3. 查询用户数据、冻结快照、过滤候选，再调用 ranker；此时没有 SQLite 写锁。
# 4. 短写事务重查同日缓存和候选审核/链接/拒绝状态。
# 5. 一次提交快照、每日推荐和 served 事件；竞争请求返回已经提交的同日记录。
# 6. 空候选返回 none，不编造内容；30 天内推荐过的单集排除。
```

```text
时间约束：
  新快照 as_of 由服务采集后生成，不接受调用方指定过去/未来时点重建历史。
  交易日期/明确时刻在 as_of 之后的记录不作为实际收支；未来开支和预计收入只是当时已知的安排。
  updated_at/created_at/timestamp 晚于快照的输入拒绝使用，相应来源完整性置为 False。
  储蓄状态只取 recorded_at <= as_of 的追加版本；未来修正不能改写旧目标版本。
  保存后 snapshot_id 对应的 JSON 永不覆盖；load_snapshot 校验用户归属。
  当前账本修正只影响之后生成的快照；不从当前记录“重新计算”历史快照。

缺失预处理：
  原值 None；missing_mask=1；scaled_features=0；有效原值 missing_mask=0。
  所有数值使用 sign(x) * log1p(abs(x))，正负结余符号保留。
  actual_income_* 与 expected_* 分开；transfer/internal_transfer 不计实际收入/支出。
  savings_locked_total / savings_net_transfer_month / carryover_month / available_remaining_month 独立字段。

降级：
  新用户无有效记录 -> insufficient_finance_data；来源失败/不完整/无效交易 -> finance_source_unavailable。
  HSTU 超时 -> timeout；连接失败 -> connection_error；无效响应/配置 -> invalid_response_or_config。
  shadow 返回基线，并把外部 model_version/scores 写入每日记录 ranking.shadow。
  SQLite 每日推荐持久化本身不可用时返回 503，避免无持久化约束却返回多条推荐。
```

## 3. 路由接口 schema

机器可读定义：`docs/api/finance-podcasts.openapi.json`。

```text
GET  /api/podcasts/today
  新字段 recommendation_id / as_of / evidence / fallback / fallback_reason / ranker_used
POST /api/podcasts/feedback
  program_id / kind / recommendation_id / event_id / value
  view/follow/dislike 保持旧请求兼容；helpful 必须绑定 recommendation_id，value 默认 true
  undislike 恢复本人推荐，追加独立事件，不删除历史 dislike；旧 SQLite 事件表自动事务迁移
POST /api/podcasts/events
  kind=impression，必须绑定本人推荐与内容；每次实际曝光使用独立 event_id
GET  /api/decision/funds
  carryover_month / available_remaining_month / savings_locked_total / savings_net_transfer_month
  complete / reason / as_of / month；未知金额 null
POST /api/decision/funds/carryover
  month / amount / event_id；确认本月或过去月份，金额可负，事件重试幂等
GET/POST/PUT/DELETE /api/dashboard/goals
  旧接口形态保留；写入转为 SQLite 目标投影、版本与内部资金划拨原子提交
```

```text

响应 HTTP 200，所有候选恰好一个有限数值分数，无额外/重复/缺失候选。
```

```text
PODCAST_DB_PATH 同时保存推荐、不可变快照、目标和内部资金账目；全部后端进程必须共用同一本机持久化路径。
mode=baseline 不调用外部服务；shadow 仅记录有效外部分数；hstu 使用有效外部分数，否则自动回退 B1。
连接超时最多 1 秒、读取超时配置值（0 < timeout <= 30），读取期间检查累计耗时及响应大小，不跟随重定向。
切换模式不重排已生成的当日推荐。历史 snapshot 版本保留 v1；新快照使用 finance-context-v2。
```
