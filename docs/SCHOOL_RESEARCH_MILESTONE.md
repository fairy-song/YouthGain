# 学校研究首个里程碑：使用与实现说明

实现日期：2026-10-07。当前实现为中央差分隐私研究原型，默认开放模拟演示。真实数据流程已实现，需通过服务器配置显式启用，学生逐项目主动加入。未实现联邦学习或群体 PCA。

## 入口与操作

- 学生：登录后进入“我的 → 研究参与与隐私设置”，或 `/#/research/participation`。阅读用途和范围、勾选同意、确认参与；从下一个完整自然月起贡献，随时可退出。
- 学校研究者：`/#/research`。平台管理员按已验证邮箱授予指定项目权限和截止日期；研究者登录普通账号即可查看获授权项目的快照。研究权限独立于平台管理员权限，不继承用户管理权限。
- 未验证邮箱的真实账号可在学校研究页主动发送验证邮件；完成后点击“已验证，刷新权限”，重新取得身份令牌。页面不会自动发送邮件。
- 平台管理员：管理员页面的“学校研究管理”，或登录管理员账号后访问 `/#/research`。建立项目、授予/撤销研究者权限、发布已结束月份、查看预算记录。
- 导出：每月快照下载为 JSON，内容与看板同源，不包含参与学生 UID、明细、精确参与人数、备注或聊天。

可以先创建一个“模拟演示数据”项目，研究月份填写已结束的月份，例如 2026-09 至 2026-09，再生成该月快照。模拟源为200名程序生成的参与者，不读任何账号消费记录，不消耗真实数据的累计预算；模拟结果始终带来源标签。

真实研究项目不能追溯创建历史研究期。若学生在2026年10月加入，则最早贡献2026年11月，12月起可生成11月快照。未参与者不会被研究读取，退出后不会进入后续新生成的发布；已发布结果仍保留。学校名称是项目说明，本原型没有接入学籍验证，不能声称参与者已通过学校身份认证。

## 运行配置与依赖

安装 `backend/requirements.txt` 后重启后台。研究功能使用 `diffprivlib==0.6.6` 与 `scikit-learn>=1.7,<1.9`，依赖要求 Python 3.10+。1.9移除了该版本 diffprivlib 导入的树常量，已约束兼容版本。

配置项见 `.env.example`：

```dotenv
RESEARCH_LIVE_ENABLED=false
RESEARCH_DB_PATH=
RESEARCH_GLOBAL_EPSILON_MILLI=6000
```

`RESEARCH_LIVE_ENABLED=true` 才能建立真实项目并接收同意/发布；关闭后停止新增参与和真实发布，已有快照可读，学生仍可退出。开发认证绕过仅用于本机测试；正式研究使用真实认证，研究者邮箱需通过验证。

研究账本独立于现有 MySQL / Firestore / 开发记账存储，使用 SQLite 事务。开发内存模式默认保存为 `backend/research.db`；其他开发模式默认位于 Flask instance 目录。生产环境必须明确配置 `RESEARCH_DB_PATH`，所有后端进程使用同一本机持久化路径，并设置操作系统文件权限。不是多主机或无状态容器存储方案；多主机部署前需迁移到共享事务数据库。

初次创建账本时保存全平台累计预算上限，默认 ε=6。后续修改配置不会增加余额。不得删除账本、更换路径或恢复旧备份来重置预算；研究账本与已对外发布的快照必须一并纳入备份和恢复审计。应用不提供预算重置、重新抽噪或项目数据模式修改接口。

## 三个指标的准确口径

1. 月度已记录支出分布：无有效记录、(0,500)、[500,1000)、[1000,2000)、[2000,3000)、[3000,+∞) 元；每个参与账号只进入一个桶。
2. 类别占比向量：餐饮、交通、购物、娱乐、学习、其他、无有效记录。单个学生有记录时归一化为总和不超过1的类别占比；无记录时进入固定缺失桶。发布的是包括缺失状态在内的学生平均份额，不是全体金额加总后的消费占比。
3. 支出与预算比较：预算缺失/为零、无有效记录、低于50%、50%至100%、超过100%。预算取发布时账号资料中的月收入或生活费，不能解释为历史月份曾设置的预算。

当前按每个同意账号发布时可读取的最近最多2000笔消费记录，选取目标月的有效正数金额。非法日期、无效金额及单笔超过现有产品金额上限的记录不参与；截取和缺失不会通过独立人数或错误计数返回给研究者。此上限及漏记会影响研究效用，已在学生说明和快照中标注。后续可增加专用月度数据查询以改善完整性。

## 隐私机制与预算

保护邻接关系是增加或移除一名学生的全部贡献。每次发布包含三个固定维度向量：每个向量的单人 L1贡献不超过1，拼接后敏感度不超过3。每个坐标使用 diffprivlib 的 Laplace 机制，ε=1、δ=0、sensitivity=3，独立噪声尺度为3。整个拼接向量的一次发布按 ε=1计费，不是每个坐标额外发布一份预算。

生产随机源为库默认 `SystemRandom`，未设置固定随机种子。截负值为零、归一化成比例、四舍五入、下载和图表展示都是对同一受保护结果的后处理。

显示门槛使用加噪并截零后的支出区间向量之和是否达到30，而不是精确人数。它是信号门槛，不保证真实人数至少30；未达到门槛仍保存固定快照并计费，不能不断重试直到出现图表。噪声误差说明为单个坐标的理论范围，不是比例的置信区间。

每个项目最多6个月、每月一个固定版本快照，项目预算等于月数乘以1。所有真实项目还受同一个平台累计预算限制，因此换项目、学校或研究账号不能重置累计发布成本。该全局策略保守地覆盖跨项目及跨月份组合；不按照私有参与者名单决定是否能扣费。

SQLite `BEGIN IMMEDIATE` 在读取预算之前获得写事务；预算检查、随机结果、快照、预算流水和发布审计在同一事务提交。响应仅在提交成功后返回。重复发布的标识为“项目ID:月份”，并发重试读取同一份已存结果。提交失败返回503、回滚预算和快照，不暴露随机生成但未提交的结果。

这套机制的保护范围是研究发布结果，依赖可信青盈后端、正确身份与预算账本、贡献边界和安全运行环境。功能测试与使用成熟机制库不能代替独立的隐私实现审查；ε=1的月度设置及累计ε=6是当前原型参数，正式试点需评估其效用与适用性。

## 保存与权限

研究贡献即时提取，不额外保存特征表或原始账单副本。保存项目配置、研究者授权、同意状态、受保护快照和预算审计。项目结束90天后，下次研究服务访问会清除该项目的学生同意标识；新的真实发布也会在此期限后被拒绝。已发布快照和累计预算审计长期保留，避免忘记既往发布成本。退出研究不删除个人账本。

研究服务对各个快照查询和导出重新校验项目授权及期限，不依赖前端隐藏按钮。研究者不能发布、修改项目或访问平台管理员接口。管理员授权操作和导出有审计记录；学生不被列入研究者可访问的列表。浏览器响应设置 `Cache-Control: no-store`，服务器内部快照持久化。

## 验证

```text
python -m pytest backend/tests/test_research.py
npm test -- --watchAll=false --runInBand --runTestsByPath src/pages/Research.test.js
python backend/evaluation/research_privacy.py
```

后端测试覆盖授权、邮箱验证、到期/撤销、学生同意、退出、预算组合、重复发布、并发、生成失败、数据库提交失败、模拟隔离、保存期限、特征边界和安全随机源。前端测试覆盖主动勾选、退出、研究者只读、快照导出和管理员操作。

效用脚本只使用模拟数据，比较30、100、300个参与者下的抑制次数与发布后比例平均绝对误差。每轮模拟独立单次发布，不对应真实用户上的连续查询，不代表实际研究效果。

2026-10-07 的一次运行结果（每组50轮，安全随机噪声，每次运行会变化）：

| 模拟人数 | 不展示分布的轮数 | 展示时各坐标比例的平均绝对误差 |
| --- | --- | --- |
| 30 | 23/50 | 7.211 个百分点 |
| 100 | 0/50 | 2.417 个百分点 |
| 300 | 0/50 | 0.922 个百分点 |

这是固定模拟分布下的原型效用检查，不能用作真实学生群体的误差承诺；展示时误差也受到抑制筛选影响。

参考：[NIST SP 800-226](https://csrc.nist.gov/pubs/sp/800/226/final)、[diffprivlib 机制文档](https://diffprivlib.readthedocs.io/en/latest/modules/mechanisms.html)。
