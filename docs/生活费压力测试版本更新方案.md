# 青盈生活费压力测试版本更新方案

**日期** 2026-11-05

**状态** 首版已实现，待校园试用

## 本轮实施计划

1. 已在首页复用资金快照和未来开支列表。用户手动带入当天已确认的参考余额，并勾选仍未支付、尚未扣除的开支。缺少账本数据时可以手填。
2. 已接入首页入口、表单和对照结果。可用内置示例验证，提交后自动定位到结果。
3. 完成工程验证后，用模拟案例开展小范围试用，记录卡点，再按反馈确定下一轮。

## 更新目标

让大学生在下一次收入到账前，能看清哪些开支需要先留，以及购买、推迟购买或收入晚到会怎样改变资金安排。优先优化首页现有资金卡片，提供「试一笔消费」入口。适用时刻包括生活费到账、拿不准一笔消费、隔几天回来重新检查计划。

## 用户体验与首版范围

1. **确认三个信息。** 当前能安排的资金、下一次预计到账日、到账前要留的开支。已有记录时带入参考值和明细，请用户核对；记录不足时允许手动输入本次试算的金额。另可填写日常开销估计，留空时结果只覆盖已列出的开支。
2. **比较两种安排。** 默认展示当前计划。用户可加一笔模拟购买，或把预计到账日期往后移。并排显示预计到账前剩余资金、首次不足日期和当日缺口；结果旁注明使用了哪些记录和假设。
3. **核对取舍。** 点击模拟支出可复用钱币展示。结果保留「查看明细」和「调整假设」两个入口，资金不足时给出可直接试算的动作，例如推迟购买或核对遗漏开支。

首版交付首页入口、试算表单、方案对比和计算明细。AI 教练解释、消费模式匹配微课或播客、主动提醒，放在首版试用之后评估。

## 计算规则与实现位置

| 部分 | 建议做法 |
| --- | --- |
| 首页接入 | [TodayHome](../src/pages/TodayHome.js) 首屏增加可展开的 [试算入口](../src/components/LivingFundsStressTest.js)。[每日均分](../src/components/DailyFundsBreakdown.js) 仍使用月度口径，试算单独展示到账周期和输入假设。 |
| 起始金额 | 参考现有 [资金快照](财务推荐v2模块定义.md) 的已记录日常可用资金；用户也可覆盖为「本次试算可用金额」。快照缺失、未确认或过期时请用户确认，缺失金额按未知处理。起始资金已排除的储蓄锁定和预留资金不再扣减。 |
| 计划开支 | 复用 [目标资金规划器](../backend/app/services/goal_planner.py) 的未来开支与预计收入字段口径。只纳入尚未支付、且未从起始金额扣除的开支；必要开支单列，日常开销估计只填写未被单列覆盖的部分。模拟购买单独显示。 |
| 时间线 | 以用户时区的当地日历日为准，从今天算到预计到账日前一天。逐日用上日余额扣除当天计划开支、日常估计和模拟支出，全部以整数分计算。预计到账用于界定周期，收入实际到账后才进入账本资金。 |
| 实现边界 | [逐日计算](../src/utils/livingFundsProjection.js) 独立于界面，输入仅保存在当前页面。两个方案用相同起始资金，不写账单、结转和储蓄数据。若后续接入 [AI 教练工具](../backend/app/services/coach_tools.py)，由同一套计算规则输出数字和假设，模型负责解释。 |

**示例。** 今天有 ¥600，到账前另需预留 ¥200，日常开销按 ¥20/天估计。若今天买 ¥129 的耳机，12 天后预计剩 ¥31；若晚到账 3 天，15 天后预计差 ¥29。按输入日期展开时，页面还应标出余额首次低于零的那一天及当日缺口，和周期末结果分开显示。

## 验收与试用

| 场景 | 验收标准 |
| --- | --- |
| 同一计划下比较方案 | 示例的两种结果分别是 ¥31 和 −¥29；移除模拟购买后可恢复基准结果，账本不产生新记录。 |
| 开支已记账或已扣除 | 不再次计入预计支出；同一笔日常费用不会在单列和每日估计里同时扣除。 |
| 没有日常估计或到账日期 | 缺日常估计时只显示已列开支的试算结果；缺到账日期时提示补充，不显示可能误导的撑过天数。 |
| 当天到账、跨月或跨日 | 首版预计到账日必须晚于今天，含延迟最多 90 天。跨月按日期连续计算，隔日重新确认起算日。 |
| 结果解释 | 能核对起始金额、支出清单、时间范围和每笔模拟变动；不足状态同时提供文字与金额。 |

先邀请 5 位同学完成两项任务：在没有操作讲解时试算一笔购买，以及在到账延迟后调整计划。记录能否独立完成、在哪一步卡住，以及能否解释首次缺口。若有人把试算结果当作银行余额，优先修正文案与信息层级；若反复卡在开支预留，先改表单再复测。

可用性稳定后，再换一个新场景并撤去提示，观察学生是否主动预留必要开支、考虑收入延迟、在条件变化后调整计划。工程测试和示例验证不能代替校园试用。

## 上线与回退

- 本地开发默认开启，普通生产构建默认关闭。需要构建试用包时设置 `REACT_APP_LIVING_FUNDS_STRESS_TEST=true`；需要关闭时设置为 `false` 后重启开发服务或重新构建。首版无数据库迁移，回退无需恢复用户数据。
