# 目标资金安排

## 简化后的入口

不再展示独立的大表单。我的目标区域只显示估算可花金额和“调整计划”入口，每个目标卡片直接显示当前预留、下次到账后预留及缺口。计算说明、后续多期安排和目标编辑默认折叠。新增目标的已存金额变为可选折叠项。

首次打开时，服务器从已有月收入/到账日生成未来收入草稿，并带入未处理的待支付事项；余额留空，不根据月收入猜余额。用户补余额并确认必要开支后才生成建议。草稿只预填，不自动保存或确认收入到账。资料不足时允许在折叠的收支安排中补充。已有安排继续复用，过期快照仍要求核对余额，尚未实现自动对账和收入到账确认。

目标的 deadline 表示实际付款截止日；预算应包括门票、交通等目标成本。
仪表盘新增资金安排表：用户确认当前总余额（包括目标已有预留）、安全缓冲、规划截止日和带日期的未来收入/必要支出。

算法以分为单位运算。先扣除安全缓冲和所有进行中目标的已有预留，按照日期保护未来必要开支；使用现金流的后缀最低余额确定每次到账可用于目标的增量。任一时点存在基本资金缺口时，不再分配新增储蓄。目标按付款截止日排序，共用同一资金池；每个目标按可用余量比例分配到各期，同日付款不依赖同日预计收入。同日必要支出先于收入，采用保守口径。

例如付款前两次到账各有 500 元余量、当前无余量，580 元目标分为两次各 290 元。若所有资金当前已到账且没有未来收入，资金现在预留；不会因为时间经过而机械逐日扣款。

这是保存的计划快照，不是账户连接或自动执行。不会生成流水、修改实际余额或自动增加目标已存金额。用户可在目标卡片更新实际预留和付款日期。付款后正常记账，点击“已付款，结束预留”，并确认付款后的余额。日期或目标金额、状态、预留、日期变化会使旧计划失效，必须重新确认。当天其他收支发生后也须主动更新余额及删除已发生的计划收支。

规划须覆盖全部进行中目标；用户应填写区间内全部必要开支，建议覆盖最后一次目标付款后的收入周期。数据遗漏、不确定收入及日期错误会影响结果。该估算并非自动验证过的真实可支配余额。

API：GET/PUT /api/decision/goal-plan，按认证账户隔离，复用 learning_entries 存储，不需要修改 goals 数据表。
