# 青盈情境化财商实践改进计划

日期：2026-11-06。基线：8372201317df66d2a71125b7a5664da27106d6c0。

## 目标与现状

对应题目：融合行为经济学与情境化智能辅导及个性化推荐的大学生财商实践平台。
当前无真实试用用户；本轮验证可用性和数据正确性，不宣称改善财商或验证算法有效。
已有账本、全月分类汇总、钱币展示、教练授权、音频推荐和每周复盘。主要缺口是这些能力之间缺少连续路径。

## 实施计划

1. 首页优先呈现消费感知：使用后端全月分类汇总，用户选择类别后查看人民币面额展开。不能使用最近一页账单冒充全月统计。
2. 用户确认自己的感受：符合预期、比预想多、尚不确定。不给用户贴冲动消费标签，不把金额等同于浪费。
3. 将用户确认的观察带到已有教练或复盘，进入后仍需用户确认发送或保存；沿用教练资料授权。
4. 首页提供低频返回路径：导入已有账单、回看上次行动、查看已有知识推荐。数据缺失时解释范围，不把零记录说成零花费。
5. 减少视觉堆叠：连续编排、留白、清晰主次；数字换算有静态等价内容，手机与键盘可操作。
6. 模拟首次、已有消费、退款、数据缺失、请求失败、低频返回和三端独立场景；运行测试与生产构建，浏览器验证桌面和手机。

## 本轮边界

复用后端月度收支口径、已审核内容推荐与现有复盘存储；不新增财务余额写入，不建立第二套账户数据。
本轮推荐仍由已有推荐服务产生，不声称按新页面临时选择实时重排；提供推荐依据与反馈入口。
三端独立路由与权限保持，学校端不增加学生个人消费明细访问能力。

## 回退与数据

新增独立环境开关 REACT_APP_SPENDING_JOURNEY=false，重新启动/构建可关闭消费感知入口与复盘带入增强。
原有账本、教练、推荐、复盘仍可直接使用；没有数据库迁移。模拟测试使用隔离浏览器与接口样例，不修改真实用户数据。
全量撤回本轮可根据本文件列出的基线与最终 diff 还原对应代码；不使用破坏性整体重置。

## 验收与后续

先交付可运行的消费感知—解释—自主行动—回顾路径，再招募 5—8 名同学做探索性试用。
收集任务能否完成、信息理解、推荐相关性、输入负担和是否自愿再用；不以点击或演示样例充当效果证据。
实施后补充实际测试结果、已知限制和真实试用任务。

## 本轮实施结果

- 已在学生首页连接“分类累计消费 → 确认个人感受 → 带入教练/复盘 → 回看上次行动”。
- 复用人民币面额展示，不新增粒子或图形依赖；保留面额、数量、合计与静态内容，兼容减弱动效。
- 以分核对分类净额与全月总额；缺失、异常或汇总不一致时不展示消费结论。退款净额为零/负数时不渲染成正向支出。
- 用户切回页面时，未变化的汇总保留类别和感受；更新期间暂停带入，金额变化后重新确认。
- 教练入口仅预填观察；默认不勾选额外资料授权、不自动调用模型。复盘需主动带入、填写下一步并保存，带入时保留正在编辑的文字。
- 音频推荐可带着节目标题进入教练，明确未取得全文时不可编造；不把进入教练记成收听或有帮助。
- 原有推荐算法、每周复盘存储、三端权限与数据结构保持兼容。更新 README 与环境配置说明。

## 对题目的具体支撑与待验证假设

| 方向 | 本轮实现 | 真实试用需要验证 |
| --- | --- | --- |
| 行为经济学 | 将累计金额转为可见面额，让用户对照自己的预期，提供自主选择的下一步 | 是否帮助理解消费规模，是否引起不必要压力 |
| 情境化智能辅导 | 将确认过的消费事实与感受带入已有教练，先追问用途与安排 | 回答是否贴合情境、有依据且帮助自主思考 |
| 知识推荐 | 复用已有推荐理由和反馈，将学习内容连接到实际问题 | 推荐是否相关、能否用于生活，不能只统计点击 |
| 财商实践 | 保留自己决定的行动，后续回来可回顾和修改 | 低频使用者是否仍能完成有价值的一次实践 |

上述是设计假设，不是经过实验验证的结论。

## 验证记录

1. 最终前端测试：40 个测试套件、259 项测试通过。覆盖金额与退款核对、数据不足、确认发送/保存、草稿保留、后台刷新及关闭开关。
2. 最终生产构建成功，JS gzip 556.05 kB；现有大包告警仍存在，本轮未做独立的首屏拆包优化。
3. 新流程浏览器模拟：390px、1280px 各 6 项，共 12 项通过。包括空账本入口、钱币到教练、确认复盘保存再返回首页、推荐到教练、退款抵消、失败重试；检查页面异常、横向溢出与非主动写入。使用减弱动效设置。
4. 原有三端回归：20 个场景通过，包含登录、入口隔离、双标签页不同账户、问卷意图保存、独立失败恢复。旧脚本另外两项默认试算已开启；生产构建沿用默认关闭配置，改为核验“该开关仍独立关闭”，两种宽度均通过。试算本身由既有单元测试覆盖；不把这两项写成生产端试算操作成功。
5. 浏览器测试全部拦截 API，使用标记的检验样例；未操作真实资金、写入真实账户、调用付费 AI 或发送邮件。未验证真实 Firebase 认证或模型回答质量。
6. 本地开发服务已就绪，当前源码编译成功；入口 http://localhost:3000/#/ 。

可重放的新流程脚本：`scripts/test-spending-journey.cjs`。需要本机可用的 Playwright 和浏览器可执行文件，以参数传入；没有加入运行时依赖。

## 回退步骤

1. 在本地环境配置中设置 `REACT_APP_SPENDING_JOURNEY=false`，重新启动前端；生产部署需重新构建。配置只关入口增强，不删除复盘记录。
2. 首页关闭新观察区，恢复原有标题与资金/练习路径；音频到教练入口及复盘带入提示同步关闭。
3. 若需完整撤回，针对本轮独立提交做反向提交；不要删除数据库、替换个人配置或对工作区执行整体重置。

## 同学试用任务（下一阶段）

先访谈最近一次真实的消费困惑，再给出任务，不提前解释界面答案：

1. 找到一类你想了解的花费，解释显示金额的时间范围和退款关系。
2. 对照原来的感受，选择了解用途、询问教练或记录观察；允许跳过。
3. 自愿确定一个与生活有关的下一步，并在第二次使用时找回它。
4. 评价一条推荐是否相关、依据是否清楚，并反馈“不感兴趣”或“有帮助”。

记录是否独立完成、卡点、金额理解、建议相关性、输入负担与再次使用理由。样例数据和个人数据分别注明；参与者可不提供个人账单。暂不把少花钱、完成练习或连续使用视为财商提升的证明。

## 已知范围

当前消费观察以本月分类汇总为范围，不自动识别因果、冲动消费或跨月长期趋势；不是新增训练好的行为模型。推荐沿用已有服务，不按临时选择实时重排。回顾仍按周存储，低频使用者可以在文字中注明更早的观察时间。真实用户需求、AI回答质量、推荐效果和长期意识变化，留待真实试用与后续研究验证。
