# 青盈三端界面改进方案

## 本轮实施计划

1. 先保留三端现有路由、数据口径与权限。学生端整理「今天」首屏，管理员端以管理概览、知识审核及播客审核为入口，学校端以项目和月份为报告导航。
2. 使用青绿、暖白和墨色，通过字号、对齐、留白与细分隔建立层次。学生端用资金与时间线组织内容，管理员端用队列和详情，学校端用报告页与可读图表。
3. 对照原页面走查关键任务。学生完成试算并看见缺口，管理员核对内容后完成审核，教师能定位月报并导出同一份快照。检查窄屏、键盘、无数据、失败恢复和角色边界。

方法参考 [Design Council 的小范围试做与验证](https://www.designcouncil.org.uk/resources/framework-for-innovation/)、[Apple 界面设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles/) 和 [Ant Design 设计价值观](https://4x.ant.design/docs/spec/values)。

## 首轮交付

| 入口 | 实际调整 | 验收任务 |
| --- | --- | --- |
| 今天 | 以可用资金为首屏重点，未来开支使用时间线，练习和音频依次展开。 | 查看待留开支并完成一次模拟试算。 |
| 管理后台 | 默认进入平台概览。知识与播客使用状态筛选、队列和证据详情；播客发布或撤回要求确认。 | 核对来源、确认操作，再查看结果提示。 |
| 学校研究 | 按项目和月份查看一份报告，区分模拟、可读统计和信号不足，导出当前月份。生成快照前提示预算影响。 | 找到指定月报、确认来源并导出同一份快照。 |

首轮用模拟数据验证，未进行真实内容发布、研究快照生成或上线。下一轮优先用同样的三个任务观察首次使用者的卡点，再决定是否推广到其他页面。

## 第二轮实施计划

1. 以首次访问学校端的老师为验收角色，从首页可见入口开始。老师使用现有青盈账号登录，登录后直接进入学校端，由服务器核验学校授权。
2. 登录前区分已获授权、需要注册或验证邮箱、只想看演示三种情况。登录后给未验证与未获授权的账号不同的下一步。公开演示只用固定模拟数据。
3. 使用全新的浏览器会话验证从首页发现入口、登录后回到学校端、未授权恢复和免登录演示。复核手机首屏是否能看见入口。

### 学校端使用路径

- 老师在青盈首页点「学校端」。已登录的账号直接核对项目授权；未登录时进入学校专用登录页。
- 老师使用项目负责人授权的邮箱和现有青盈密码登录。首次注册用同一邮箱，正式账号按页面提示验证邮件。负责人在管理员端进入「学校研究管理」，选择项目并在「管理学校研究授权」填写老师邮箱及截止日期。
- 没有账号或授权也可点「演示月报」，体验固定模拟数据的报告。演示页不读取项目接口，也不包含任何真实学校或学生记录。
