# v1.17 待付款处理链路

状态：已验收。用户授权的专项续改，不计入当日例行任务。

## 批评及验收条件

1. 首页指出具体事项，跳转后却丢失事项身份。改为携带本人事项 ID，到账本后聚焦该条；不存在的 ID 给出提示，不读取其他账户内容。
2. 必须先标记处理才出现记账入口，先后关系不自然。未处理事项直接带入现有记账表单，保留替换已有草稿的确认。
3. 记账与结束预留是两件事，缺少接续。记账成功后可确认已全部支付，状态更新失败只重试该状态；记账失败不得结束事项；部分支付可保留待支付。

不新增自动扣款、不修改账务口径，不把标记处理当成财务支出。没有修改真实账单。整批撤销发布提交可回退，无数据库迁移。


## 使用顺序

首页待付款 → 对应事项自动定位 → 去记这笔支出 → 核对实际金额、日期与类别 → 保存账单 → 确认已全部支付或保留待支付。

- 已经记账或无需再付：展开“已记账或无需支付？”后手动标记处理。
- 已处理但确实漏记：展开“已处理但还没记账？”，先核对账本，再选择补记。
- 记账失败：保留草稿，不改变事项状态。
- 账单已保存、状态更新失败：重试“确认已全部支付”，只更新状态，不重新记账。
- 仅支付一部分：保留待支付；本版本不会自动计算剩余应付款，原计划金额不变，规划可能继续按原金额保守预留。

## 边界与继续改进

本版本的账单保存和事项处理仍是两个请求；确认处理需要本人操作。刷新页面后，未处理事项仍会保留，需先在账本核对再决定是否补记。没有新增跨刷新自动关联或账单提交幂等键，也不承诺网络断开后的任意重提都能自动去重。
