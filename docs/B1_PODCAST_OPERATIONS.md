# B1 每日音频博客：内容与运行说明

青盈在“今天”页面**每次只推荐一期具体音频**，展示单集标题、内容简介和直达收听链接。每天同一账户的选择保持稳定；只保存平台公开的标题、简介和链接，不下载、转录或托管音频。没有合格单集时显示空状态。近期听过的单集会降权；目录暂时不足时可能再次出现。

## 第一次上线

1. 为所有后端进程配置同一个持久化 `PODCAST_DB_PATH`。这是单主机 SQLite 实现；多主机部署需要先迁移到共享事务数据库。Windows 环境安装 `tzdata`（已写入后端依赖）。
2. 新数据库首次请求会加入 8 期初始音频，来自[每天5分钟理财小知识](https://www.xiaoyuzhoufm.com/podcast/6a0fc0877766d9e550f7beb7)、[每天5分钟投资小知识](https://www.xiaoyuzhoufm.com/podcast/6a0fc0694e1b6f98d52ce1c8)和[拾光书房](https://www.xiaoyuzhoufm.com/podcast/6a227d82bd11c9e37906dbeb)。单集直达链接与简介于 2026-10-11 按公开页面核对；日期保守采用所核对单集的创建日期。旧版自动加入的 3 条节目记录会原位迁移为各自的一期单集，以保留当天已保存的推荐。设置 `PODCAST_STARTER_CATALOG_ENABLED=false` 可关闭初始化。初始目录需继续抽听和维护。
3. 管理员进入“管理后台 → 音频博客目录”，按**一期一条**继续添加。填写节目名称和主页、单集标题和直达链接、单集简介与发布日期、主题、难度、质量评分，以及商业推广／具体金融产品推介标记。同一节目可以收录多期；同一期在不同平台的链接放在同一条记录。保存后是“待审核”，复核后点击“审核发布”。
4. 若已核实公开 RSS 或取得许可，可填入 RSS 地址，并在 `PODCAST_RSS_ALLOWED_HOSTS` 中列出确切主机名。当前 RSS 同步仅更新节目描述和活跃度，**不会自动发布新单集**；新单集仍须提供直达链接并审核。喜马拉雅开放平台 API 未在 B1 接入。
5. 部署端每天运行一次 `flask --app app:create_app podcasts-sync`（在 `backend` 目录、相同环境变量下）。它只同步到期且已审核的 RSS 元数据。管理后台可手动同步某一来源。RSS 描述发生改变会回到“待审核”，管理员复核后才能再次推荐；失败保留上次资料并记录错误。没有配置外部计划任务时，后台不会自行定时读取。

## 审核边界与排序

只有已审核、质量评分至少 0.75、节目和该单集均在最近 180 天内更新或发布、复核不超过 90 天、难度合适且无商业推广或具体金融产品推介标记的单集可进入候选。有 RSS 的记录还要求最近 30 天内成功同步。来源失效、撤回或过期后停止展示。相似度不能替代内容质量审查。

用户兴趣由“我的”中主动选择的主题、12 题问卷的自述方向和近期练习主题构成；本人已记录的消费类别只提供较弱的场景线索。原始账单、商户备注、完整问卷与个人向量均不发送给第三方。第一版使用本地**主题词扩展＋字符哈希文本向量**进行相似度匹配，同时记录纯主题标签规则分数作为对照。这是可审计的轻量文本向量，不宣称已采用神经网络语义嵌入，也不依据收听、点击或消费金额推断财商能力。

30 天内推荐过的**单集**会被明显降权；若没有其他合格且匹配的单集，仍可再次出现。“收藏本期”和“不感兴趣”影响以后候选；“不感兴趣”会收起当天卡片，且该单集不会再推荐给此用户。查看、收藏、曝光可用于产品体验分析，不能代替独立的财商学习效果评估。若当天缓存了空结果，之后新增合格单集可补齐当天推荐；已经展示的单集仍保持稳定。

## 接口与验证

- 学生：`GET /api/podcasts/today`；`POST /api/podcasts/feedback`，`kind` 为 `view`、`follow` 或 `dislike`。
- 管理员：`GET/POST /api/podcasts/admin/programs`，`PUT /api/podcasts/admin/programs/<id>`，`POST /api/podcasts/admin/programs/<id>/review`、`.../sync`，以及 `POST /api/podcasts/admin/sync-due`。
- 自动化测试使用合成单集与本地 RSS 样本，不连接第三方平台；真实单集仍需人工抽听、来源核对和少量学生试用后再扩大目录。

## 待修复：点击“直接听这一期”没有反应

**状态（2026-10-11）：未解决。** 用户在“今天 → 今天推荐这一期”点击“直接听这一期”后，没有看到单集页面打开。此前已将链接由新标签页打开改为当前页面跳转，但用户再次反馈仍无反应；不能把这次改动视为修复。

排查时应先在用户实际使用的浏览器和部署环境复现，记录点击前后的页面地址、是否出现新标签页或浏览器拦截提示，以及浏览器控制台和网络请求结果；同时核对当天接口返回的 `episode_url`、页面最终渲染的链接地址，并检查是否有遮挡层或全局点击处理拦截导航。之后再依据复现结果确定修复方式，避免仅凭猜测继续改打开方式。

现有前端测试只确认链接的 `href` 和打开目标属性，构建成功也不代表真实点击能够导航。修复验收需要在实际页面点击后到达**对应单集**，并检查桌面与手机浏览器；若外部平台无法访问，应明确显示可操作的提示，不能让按钮看起来毫无反应。
