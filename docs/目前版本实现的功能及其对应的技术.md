## 3. 数据与认证

### 3.1 存储

| 数据 | 实现与边界 |
| --- | --- |
| 账户、评估、目标、手动交易等 | `user_data_service.py` 封装 memory/MySQL/Firestore；MySQL 结构见 `backend/schema.sql` |
| 资料、问卷、练习、复盘、近期安排、导入批次、自定义分类 | 复用按账户隔离的 `learning_entries`，详见 `learning_store.py`、`learning_service.py` 与导入服务 |
| 开发数据 | `_dev_db` + `backend/dev_data.json`，启动恢复，临时文件写入后原子替换；不是正式多进程共享数据库 |
| 未登录问卷 | `sessionStorage`，版本 2，提交标识和一小时未更新失效；保存成功删除临时副本 |
| 播客 | SQLite `programs`、`daily_picks`、`feedback`、`events`；每日键为账户和北京时间日期 |
| 研究 | SQLite `research_state` JSON 账本，存项目、同意、授权、快照、预算与审计 |

生产播客/研究需明确持久化路径，所有进程共用同一本机库；多主机需先改为共享事务存储。真实 MySQL/Firestore 当前最新改动没有完成本次集成验收，存储接口替身测试不能替代它。

原始账单不长期保存；标准化行、来源交易号、解析版本、批次和退款引用保留。导入后的用户信息仍是个人数据，并不因不存原文件而匿名。

### 3.2 身份与权限

服务端从已验证 token 取得 UID，不信任请求体自报账户。SDK 不可用或签名验证失败则拒绝；不会仅解码 JWT 后放行。管理员按 `ADMIN_EMAILS` 判定，服务端另校验角色；停用账户拦截需认证请求。

仅当显式 `DEV_MODE=true` 且未声明生产环境时绕过真实认证。前端通过 `X-Dev-Email` 模拟邮箱，服务端将邮箱哈希为开发 UID；它是本地测试工具，客户端可自报邮箱，不能用作公开身份验证。

公开健康和知识接口不要求登录。**当前 `/api/asr/transcribe` 也未加 `require_auth`**，不能声称所有服务接口均已鉴权；公开部署前应补语音调用的身份、配额和请求限制验收。

代码实现的是账户校验、角色和访问限制，未提供银行级加密、SOC 2 认证或「后端看不到账单」的证明。

## 4. 账单导入与统一金额

### 4.1 解析及写入

流程：文件类型/大小/行数检查 → 编码与表头识别 → 微信或标准适配器 → 标准行 → 方向/状态/币种/金额校验 → 预览 → 服务端复核 → 批次确认。

CSV 支持常见 UTF-8/BOM、GB18030 编码与引号字段，XLSX 使用 openpyxl。分类是规则与用户确认，不调用 AI、PCA 或聚类解析金额。范围为单文件 2 MB、1500 行，人民币。

去重使用文件摘要、批次状态与账户/来源/可靠交易号；两导入入口共用逻辑。无可靠 ID 的同日同额记录只提示疑似重复，不直接合并。确认可重试；逐行修改保存回退信息，批次撤销检查退款依赖。实际各存储事务边界需按部署验证，不能泛称所有数据库整批事务保证相同。

### 4.2 类型与退款

类型有 `expense`、`income`、`refund`、`transfer`、`review`。收入子类为 `red_packet`、`external_transfer`、`other_income`；本人划转中性。自定义选项记录固定 `accounting_type`，名称 1–50 字，账户最多 100 个未删除项。

退款按明确原交易引用或唯一订单依据关联原支出，保存关联来源/ID；可搜索手动或已导入支出，缺失时明确补录。累计退款不得超过原支付，待关联不进入收支。重命名不回写历史快照；删除将分类标记 `active=false`、`deleted=true`，后续列表/解析排除，历史已保存值保留。

菜单使用 React-Bootstrap 浮层而非原生 `<option>`，让文字选择与删除 × 分开；确认后关闭菜单，取消保留打开，刷新预览与管理数据源。退款关联仍用 `Collapse`，默认收起，遵守减少动效设置。

### 4.3 单一月度快照

`get_monthly_cashflow()` 合并完整交易，从北京时间本月 1 日至今天生成：`spent`、`gross_expense`、`refunds`、`income`、`remaining`、`income_breakdown`、`category_breakdown`、`daily_spending`、完整性及覆盖标记。

```text
spent = gross_expense − refunds
remaining = income − spent
sum(category_breakdown.net) = spent
```

跨月退款在到账月抵减、归原支出类别；不回写历史月现金流，原订单展示累计退款后的净支付。负分类不能丢弃。最近明细 `limit=50` 只截列表，不截月度聚合。MySQL 交易查询合并导入行、评估查询只取评估；Firestore 按实际日期排序后截取。

前端 `FinanceVisuals` 直接读取服务端聚合。圆环正扇区以正向净额合计作分母，中心以全月 `spent` 显示；负值另列。近七天逐日净额允许负数和跨月，失败显示无法汇总，不用最近列表补总额。

### 4.4 不同分析口径仍须区分

月度收支按实际资金发生日期。决策引擎/PCA 的输入则在 `_load_engine_inputs()` 将已关联退款抵到原支出，保留正的订单净额、原支付日期，再分析。因此其某月订单分析与该月现金流可能不同，尤其跨月退款；不能写成所有页面所有数字完全同口径。

资料 `monthly_income` 是预算假设，实际收入来自交易。`estimate_balance()` 按用户确认余额和净支出基线调整，收入/转账不自动充值该快照；它不是完整银行余额对账。后续修改须保留这些名称和前提。

源码：[导入](../backend/app/services/bill_import.py)、[统一汇总](../backend/app/services/user_data_service.py)、[分类](../backend/app/services/bill_categories.py)、[消费概览](../src/components/FinanceVisuals.js)。

## 5. 个性化学习的算法

### 5.1 两类画像

`context_profile()` 提取本人近期记录的情境线索：30 天内相关类别的出现、值得回看的消费、复盘及近期待支付安排。不用商户备注或金额大小推断能力；类别线索需多笔、多日期门槛，记录不可用时降级。

`learning_profile()` 根据当前版本每题最近回答，按预算、取舍、缓冲、风险四主题汇总数量、不同情境数与是否答错；状态是待观察、建议复习或已有证据。不是校准的掌握概率。

### 5.2 候选与排序

先过滤 `draft`、`withdrawn` 和缺正式审核元数据的题，检查前置解锁；候选为未做题和到期题，优先完成已开始的情境链。

规则分数包含：答题缺口主题 +30、自选主题 +15、消费情境匹配 +12、新多步情境 +15、复习题 +22、基础题 +2。推荐返回当前一步、理由及理由来源；用户仍可换情境。排序是确定性规则，不是训练出的推荐模型。

题库为代码维护的 32 道 `pilot`：8 道原选择题与 8 组三步情境。元数据有知识点、难度、时长、前置、内容版本、来源和审核状态。接口不下发标准答案；开源文件仍可读答案，所以适用于形成性练习，不是保密考试。

选择/数字题在服务端评分；开放题只记录与提示。提交记录带当时内容版本，重复同题不增加独立迁移证据；旧题库版本不混进当前推荐。

### 5.3 复习调度

答错间隔 2 天；一般间隔 7 天；迁移题满足同知识点至少两项不同情境正确证据时可到 14 天。生成 `due_on`，用户进入学习时推荐到期题；无主动推送服务或后台自动教学，也未使用 SM-2、FSRS、BKT/DKT。

当前可能再次推荐同一道题，不保证自动产生不同数字的迁移题。独立新情境复测仍是路线图任务。

源码：[选题与评分](../backend/app/services/adaptive_learning.py)、[画像](../backend/app/services/learning_profiles.py)、[多步题库](../backend/app/services/learning_question_bank.py)、[前端卡片](../src/components/AdaptivePractice.js)。

## 6. 决策计算、目标与 PCA

### 6.1 确定性引擎

`decision_engine.py` 是不依赖数据库、Flask 或 AI 的纯函数，历史金额分析使用浮点与显式舍入；账本和资金分配另使用 Decimal/整数分，不能写成整个系统完全没有浮点运算。

| 功能 | 规则与边界 |
| --- | --- |
| 机会成本 | 金额 ÷ 月均结余 × 30，折算等价结余天数；结余非正时拒绝，条件估算不含收益 |
| 固定费用 | 用户指定优先；自动识别需跨月、月份覆盖率 ≥60%、月额变异系数 ≤0.20、月均笔数 ≤2 |
| 六类模式 | 到账后集中、深夜、周末、类别变化、小额高频、回访后悔集中；每类有自己的门槛/证据，不作心理诊断 |
| 目标可达性 | 目标、已存、期限和历史结余的条件估算；不模拟投资收益 |
| 后悔汇总 | 依据用户回访，不把未回访判为后悔 |

`goal_planner.py` 另做日期现金流：先保护必要开支和缓冲，按资金曲线的后缀最低余量限制目标容量，多目标在共享资金池中按期限与容量分配。同日采用保守排序，预期收入不能在到账前消费。规划用整数分，不更改实际账本或银行余额。

### 6.2 单账户 PCA

`weekly-pca-v1` 的样本是本账户有记录的完整自然周，至少 12 周、最多最近 26 周。排除首个不完整周、当前周和未来记录；空白周不填零，读取不完整不生成结论。

特征为每周频次、平均单笔、小额占比、周末占比、本人前三类别金额占比及可选其他占比。去掉常量列，标准化后用 NumPy SVD；朝 80% 累计解释方差选取但最多三主成分，上限可能使保留方差低于 80%。按最大绝对载荷统一符号，输出载荷、平方贡献、周得分与限制。

类别词表只从本人记录拟合，未训练跨用户模型。解释方差不是准确率，主成分不是财商分数；PCA 不参与账单金额、客观评分或当前学习选题。

源码：[引擎](../backend/app/services/decision_engine.py)、[资金规划](../backend/app/services/goal_planner.py)、[PCA](../backend/app/services/pca_service.py)。

## 7. AI 教练与知识检索

当前 `/api/coach/chat` 调用 `ZhipuAIService`，默认模型 `glm-4-flash`，可由 `ZHIPUAI_MODEL` 调整。SDK 超时 30 秒、最多一次 SDK 重试；无完整回答时另有一次修复请求。真实费用与配额不沿用旧稿的免费额度说明。

知识检索是中文双字片段词面基线，从站内文章正文分段并结合标题/摘要打分，最多三篇，弱匹配不选。没有向量数据库、联网事实搜索或神经嵌入；同义改写召回有限。

用户消息、最近最多十条对话历史和检索片段送模型。显式 `use_learning_context=true` 后增加本人资料、最近五条学习记录和计算汇总；不默认追加原始账单文件及交易备注，但主动聊天/学习文本仍可能含用户自己输入的信息。

`compute_facts()` 给出记录范围、完整性、试算及个人 PCA 摘要。金额来源由程序计算，但模型正文允许数字与公式。**当前 `prepare_coach_answer()` 只处理格式/空回答/原始资料清单等，返回标记也说明不代表事实或计算已验证。**

历史 `validate_explanation()` 和证据渲染函数仍在代码中，但当前智谱聊天没有沿用旧稿的强制 JSON、数字拦截与严格引用校验流程。不能声称模型改写数值、引用或金融事实均会被自动阻止。

后台提示词管理写入旧 `coach_service` 配置；当前智谱服务使用自己的 `_build_system_prompt()`。MySQL/Firestore 配置保存也未完成相同持久化。界面/接口存在，不等于修改已作用于当前对话。

源码：[聊天路由](../backend/app/routes/coach_routes.py)、[实际 LLM 调用](../backend/app/services/zhipuai_service.py)、[检索与处理](../backend/app/services/coach_evidence.py)。

## 8. 每日一期音频

目录按一期一条存公开标题、简介、直达链接、节目资料、主题、难度、审核与商业标记，不下载/转录/托管音频。新库可初始化代码中的 8 期目录，设置 `PODCAST_STARTER_CATALOG_ENABLED=false` 可关闭；初始记录仍需持续抽听与复核。

本地将主题词、标题与简介分成 2/3 字片段，Blake2b 哈希到 256 维并归一化，以点积计算余弦相似度；不是 Sentence-BERT 或大模型语义向量。用户兴趣来自自选主题、问卷、练习，消费类别只是弱线索。

候选条件：已审核、质量 ≥0.75、难度适合、无商业推广/具体产品推介；节目和单集在 180 天内活跃/发布，复核不超过 90 天；有 RSS 时最近成功同步不超过 30 天。

排序综合主题基线、文本相似度、质量、活跃度与 30 天重复惩罚，收藏影响后续相关主题，不感兴趣排除此单集。SQLite 以 `(user_id, local_date)` 保持当天唯一结果；空结果可在新增合格候选后补齐，少目录不保证不重复。

RSS 仅同步已允许主机的公开节目元数据；改变后重新待审核，不自动发布新单集。Flask CLI `podcasts-sync` 与管理员同步入口已有，定时运行需外部计划任务，平台受限 API 尚未接入。

真实「直接听这一期」点击故障仍待复现修复；现有链接属性测试不能证明实际浏览器导航成功。

源码：[匹配/同步](../backend/app/services/podcast_service.py)、[SQLite](../backend/app/services/podcast_store.py)、[初始目录](../backend/app/services/podcast_starter_catalog.py)、[展示](../src/components/DailyPodcast.js)。

## 9. 学校研究原型：保留但暂停

研究同意、权限与个人学习分开。默认 `RESEARCH_LIVE_ENABLED=false`；真实项目与发布需显式启用，当前产品决定是不扩展、不启动真实试点。入口仍在我的，不能写成学校代码已删除。

已有项目级研究者授权、学生主动加入/退出、下一个完整月起贡献、已结束月固定快照、JSON 导出和预算审计；模拟项目使用生成数据。没有学籍认证，也未实现联邦训练。

三个固定向量是支出区间、学生类别份额（含缺失桶）、支出/预算比较。每学生每月各向量 L1 ≤1，拼接敏感度 3；diffprivlib Laplace 使用 ε=1、δ=0、敏感度 3、安全默认随机源。截零、归一化和显示为后处理。

展示门槛为加噪支出向量总和 ≥30，不是实际人数保证。信号不足仍保存结果和计费；项目月快照幂等，SQLite `BEGIN IMMEDIATE` 将结果、预算与审计在同一事务提交。真实全平台初始累计预算默认 ε=6，重配不能重置。

当前发布读取上限与正额过滤等口径不等于最新版月度净现金流，若恢复需先核对退款/数据覆盖。项目结束 90 天后，在下一次服务访问中清理同意标识，保留已发布快照和预算审计。可信后端仍可访问个人明细，DP 只保护研究发布结果，原型参数与测试不是完整独立隐私认证。

源码：[研究业务](../backend/app/services/research_service.py)、[隐私机制](../backend/app/services/research_privacy.py)、[事务账本](../backend/app/services/research_store.py)。
