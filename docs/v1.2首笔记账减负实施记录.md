# v1.2 首笔记账减负实施记录

## 实施计划

按已确认方案先完成P0：精简账本主要输入，将补充详情和其他记账方式按需展开；以服务端资金完整性字段统一首页、账本和资料页的未知状态与金额精度；修复旧资料路径，并让用户从相关位置直接核对资金或进入资料设置。保存反馈不要求完成额外设置，不修改既有财务计算。

保留日期、收入切换、导入、语音及原有校验；资料补充不自动保存，示例不写入真实用户账户。不恢复v1.1教学页，不同时重构推荐、学习与首页布局。

验收：无记录、只记支出、只记收入、资料完整的正负结余、退款及储蓄；补充字段提交、连续保存、失败重试、资料定位和跨页精度。界面经手机与桌面浏览器验证，运行前后端相关测试及构建。更新README、版本记录及v1.2标签，正常同步仓库；通过撤销本轮提交可回退，无业务数据迁移。

## 实际改动

1. 账本主要输入缩减为金额、类别和日期，日期默认今天且可改，收支类型仍可切换。手机上金额和类别并排，表单输入与按钮不小于44px。
2. 商户、时段、消费内容、备注、消费想法放入“补充详情（可选）”。补记、支出导入、收款导入和语音放入“更多记账方式”。折叠保留已填写值，不改接口校验。
3. 未设置月收入也可保存支出，不再为这一状态发起注定缺少条件的机会成本请求。“支出已保存，可以继续记下一笔”放在钱币展示之前；可选说明提供直接进入财务设置的链接，展开后聚焦设置标题，保留返回账本入口。
4. `available_complete` 必须为真、`complete` 不为假且金额为有限数值，才展示本月可用剩余。其余显示“资金资料待核对”，保留已知收支；首页核对入口直接展开账本期初结转表单。“我的”金额保留两位小数，已确认的零或负数仍显示。
5. 无数据分析提示仅在分析页出现；后端缺少收入的提示改为“我的 → 财务资料设置”。未改财务计算、账户权限和数据模型，无新增依赖。

## 边界与后续

这是既有流程的第一批减负，不是首页整体改版。游客试用简化、首页任务组织、教练上下文、低频回访与学习入口仍待后续验证。无真实同学试用结果，模拟验收不证明首笔耗时或教育效果。390px桌面浏览器模拟不能替代真机软键盘、输入法和读屏验收。

资料缺失不等于已透支；已确认结转也不等于银行实时余额。改动仅控制未知状态展示，不能发现用户尚未录入的账单。

## 回退与修改

本轮独立提交并标记v1.2。需要撤回时，先核对工作区，再使用 `git revert <v1.2标签指向的提交>` 创建撤销提交并正常推送；不重置主分支、不移动既有标签。撤销不会删除已保存的收支数据。后续可分别修改表单折叠、资金展示条件或资料入口，不依赖新增库或迁移。v1.1的前置教学保持撤回状态。
