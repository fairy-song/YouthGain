# B、C、D：学习内容、推荐对照与效果评估的运行说明

本轮交付的是**可运行、可复算的开发与评估工具**。它没有自动把试用题批准为正式题，也没有真实学生的学习效果结果。B2 卡内 AI 教练不在本轮范围内；学校研究端仍暂停。

## B：先把内容审核做成可执行流程

运行 `python backend/evaluation/content_audit.py` 查看题库状态；需要逐题工作表时运行 `python backend/evaluation/content_audit.py --csv docs/B_CONTENT_AUDIT_WORKSHEET.csv`。本地已生成该文件；再次导出请先另选文件名保存已填写的审核意见，只有明确指定 `--overwrite` 才覆盖原文件。工作表列出题目、选项、标准答案、解释、来源和版本，留有审核决定与备注。**该表含答案，只供内部审核，不进入公开代码仓库，也不向学习用户发布。** 当前 32 道题都仍是 `pilot`，`needs_human_review` 为真；导出或在表中填写决定不会修改线上题目状态。

内容负责人要逐题检查金融事实、金额复算、国内适用性、来源授权、误导性选项和可读性。独立复核后才在题库中增加审核人、日期、来源依据和新版本并改为 `approved`；结构检查 `audit_bank()` 会拒绝缺少正式审核记录的批准状态。学习卡现在明确显示“试用题”，避免将试用内容误认为经过验证的正式课程。实际学生试用与延迟复测仍需开展。

## C：推荐策略对照如何运行

运行 `python backend/evaluation/recommendation_benchmark.py`。脚本只读取 `backend/evaluation/recommendation_cases.json` 中预先写好的**合成**情境，不读取账户、账单或调用模型服务。报告并列给出当前规则、只按自选主题、去掉消费线索、去掉答题证据四种策略的主题命中率、覆盖率和选题；固定案例的期望主题独立写在数据文件中。改推荐规则前后可保存 JSON 报告，用文件哈希与规则版本核对变化。

这个数字仅供开发排错：四个手工案例不是代表性学生样本，也没有未展示题目的反事实作答，不能据此宣称当前规则提升财商。若以后取得**个人学习试用中自愿提供、去标识的记录**，先固定分组密钥、截止日期、测量指标和情境族，再用 `partition_holdout()` 按用户与时间划分开发和验证数据；同一用户或情境族不得同时进入两边。没有合规、足量的数据时，不训练或上线 PCA／UMAP 聚类、知识追踪或 Bandit；单账户 PCA 仍只供个人探索。

## D：个人学习效果如何汇总

`backend/evaluation/pilot_template.csv` 是空白数据模板。研究方案须先准备**不进入日常练习题库的**前测、后测和延迟测平行表单，逐题审核难度、评分规则与来源，并预先确定主要指标、测量间隔、分组方式和退出处理。参与者自行同意后才记录匿名编号、同意版本与时间；表内不要放姓名、邮箱、原始答案、账单或学校信息。`group` 只能为 `baseline`（当前规则）或 `personalized`（待评估新策略）。未到延迟测日期时用 `pending`，错过时用 `missed`；退出用 `withdrawn=true` 并记录原因。

运行 `python backend/evaluation/learning_outcomes.py --input <本地评估表.csv>`。脚本拒绝重复编号、未记录同意、越界分数、同一人重复使用测验表单和未说明的缺失值；输出只有各组人数、完成与流失、配对前后变化、延迟保持、阅读负担和双评分者的平均绝对差异。每组至少 10 个有效前后测配对才显示**描述性**组间差值；达到这个门槛也不代表统计或因果结论。输出不包含个人行或匿名编号。空模板会返回 `insufficient_data`，不会凭空显示学习提升。

目前没有经过审核的独立测验表单，也没有学生参与数据，所以 **D 的分析程序已具备，效果评估尚未实际完成**。结果发布前还需复核表单等值、分组可比性、评分者一致性、样本流失和不确定性；不能用积分、点击、答题次数或消费减少代替学习效果。
