# 手动收支记录实施计划

1. 将账本入口改为“记一笔收支”，增加支出/收入选择及相应的分类、来源和文案。
2. 扩展现有 transactions API，默认仍为支出，收入显式使用 transaction_type=income。
3. 补齐 MySQL 类型与收款分类字段及兼容迁移，保证开发存储、MySQL、Firestore 使用同一收支口径。
4. 收入计入实际到账与可用剩余，过滤出消费分析、机会成本、退款原支出选项；已有支出与账单导入保持兼容。
5. 验证收入保存、账户隔离、金额校验、分类切换、汇总、余额核对与保存失败保留输入；更新说明。

已实现上述改造，接口说明见 [手动收支接口](api/手动收支接口.md)。余额核对采用独立的实际收入基准，避免收入重复累加；旧资料缺少收入基准时提示重新确认余额。MySQL 迁移保留历史支出并可重复执行。

验证：后端全量回归通过，前端账本、今日页面和可用资金组件共 21 项测试通过；生产构建完成，仍有后台与教程页面原有的静态检查警告。
