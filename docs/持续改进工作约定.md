# 青盈持续改进工作约定

目标是让学生更容易理解花费、安排生活、获取有依据的辅导，并让管理员和学校端各自完成授权范围内的工作。任务以真实问题和验收证据为起点，不以代码量、模型数量或页面数量衡量进步。

## 每轮两项任务

| 方向 | 优先内容 | 完成依据 |
| --- | --- | --- |
| 功能与可靠性 | 财务口径、权限隔离、数据完整性、AI 与知识检索、推荐、性能 | 可复现问题得到修复，边界行为明确，相关检查通过 |
| 体验与表达 | 登录与导航、操作反馈、移动适配、可访问性、视觉、README 与使用文档 | 用户路径更清楚，界面改动经浏览器验证，文档与实际能力一致 |

两项依次推进。优先处理会导致错误金额、数据丢失、权限混淆、无法操作或理解困难的问题；之后再处理高频负担与视觉细节。没有足够价值的问题时，记录观察及待确认项，不为完成数量引入功能。遇到明确故障，可优先用两项任务处理可靠性问题，并说明原因。

## 从发现到交付

1. **读取现状**：阅读仓库规则、README、台账和相关实现；检查本地改动与远端状态。已有成果先核对，避免重复施工。
2. **定义任务**：每项记录现象、证据、受影响用户、预期行为、范围及验收条件。复杂任务先拆分，保证单次改动可审查、可回退。
3. **实现与复核**：沿用现有架构与视觉体系。低频使用、加载、空数据、错误重试、键盘操作及三端独立均按场景检查；只有相关场景才增加实现。
4. **按影响验证**：运行必要的相关测试；代码改动执行生产构建及相应后端检查。界面改动检查手机和桌面浏览器，注明模拟接口或真实接口。文档修改运行 `python scripts/check_readme.py`，必要时验证 Markdown 渲染；文档改动无需重复运行全站业务测试。
5. **同步说明**：README 保持产品定位、实际能力、预览、启动与三端入口、文档导航。详细过程写入台账，不把日常工作日志堆到 README。
6. **保存并同步**：仅暂存本轮文件，提交前检查差异；读取远端更新，使用正常快进或无冲突合并后推送，不强推或覆盖他人工作。核对本地与远端提交编号；失败时分别报告本地提交和远端状态。

## 研究与数据边界

- 财务数值由程序确定，模型辅助解释；资料不足时保留未知，不伪造余额或确定结论。
- 真实账单、账号、密钥、本地数据库与私人申报材料不进入公开提交。测试优先使用隔离的模拟数据。
- 工程测试、模型调用成功和界面截图不代表用户研究、教育效果或原创算法证据。
- 学生端、管理员端和学校端保持独立入口与后端权限校验。研究参与及个人记录引用分别取得授权。
- 破坏性数据迁移、外部付费或超出已有授权的操作应先完成可审查方案，再取得必要授权；普通修复、验证和正常推送已获用户授权，无需反复询问。

## 开源工具和设计

可以按需要检索并安装开源 skill，安装前确认来源、许可证、依赖和所执行的脚本，优先使用已有能力。记录确实采用的来源与作用，不为收集工具而引入依赖，也不执行来源不明的安装命令。

视觉以暖白、深绿、清楚的字级、留白及连续内容为基础。先解决信息顺序和操作路径，再增加装饰；减少无必要的卡片堆叠。图标、颜色和动效必须帮助识别内容或状态，尊重减弱动效设置。

## 调度与续做

### 产品版本编号

以根目录 `VERSION` 为产品版本唯一来源，当前基线为 `v1.0`。后续依次使用 `v1.1`、`v1.2`、…、`v1.9`、`v1.10`、…、`v1.15`，点号后的数字按整数递增，不按小数或字符串排序。未获用户指示不自行升级到 `v2.0`。

每批通过验收并交付的改进递增一次，不按任务数、提交数或同步重试次数重复增加。更新 `VERSION`、README 当前版本、`CHANGELOG.md` 对应条目，并为最终发布提交创建同名 Git 标签；同步主分支与该标签后核对远端。遇到既有同名标签或其他人新增版本，先读取最新状态，禁止覆盖或移动已有发布标签。包管理工具要求的三段依赖版本与产品展示版本分别管理。

用户于2026年11月8日否定并要求撤回v1.1三步前置引导，当前流程恢复v1.0。自动改进不得重新恢复该教学页、自动跳转或用相同方案包装成新功能。后续新用户体验优先减少首次选择、输入和概念负担，在实际操作中提供帮助；设计建议不视为已获实施指令。回退不移动旧标签，新发布取已使用版本序号的最大值加一，因此下一版为v1.2。

自动调度配置在维护者本机的应用中，源码本身不提供后台运行服务，也不保证克隆仓库后自动执行。任务需要本地项目、应用、网络及额度可用；不绕过额度或自动审批。若中断，台账记录已完成的检查、未完成步骤和恢复位置，下次优先续做。

每个北京时间日期最多登记两项验收完成的日常任务；重复触发先检查台账。完成状态需区分“实现待验证”“已验证待同步”“已同步”和“受阻待续”。详细日志保留实际日期、涉及文件、验证证据及回退方法；不得把未来任务写成已完成。
