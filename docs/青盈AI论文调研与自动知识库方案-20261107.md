# 青盈 AI 论文调研与自动知识库方案

调研日期：2026-11-07。本文为论文阅读与设计建议，不代表所提算法、自动发布和容量扩展已经实现。当前代码基线 b574e18。本轮未修改应用代码、知识发布状态或申报书。

## 1. 结论与研究范围

建议以“面向大学生财务情境的缺口感知与证据约束自适应辅导”为主要 AI 研究方向，以“具有明确容量和筛选记录的动态知识库”为支撑。研究对象是选择何时追问、检索、计算、回答或暂缓；不把接入大模型、混合检索、已有 HSTU 或添加多个智能体本身宣称为算法创新。

检索覆盖 2025—2026 年相关工作，包含截至调研日可取得的 2026 年 11 月预印本；重点阅读以下论文的方法、实验与局限。并非穷尽全部最新文献，也未在青盈环境复现论文结果。会议论文和预印本分开标注。

## 2. 重点论文与适用性

| 论文及状态 | 方法与阅读结论 | 青盈取舍 |
| --- | --- | --- |
| [Sufficient Context](https://arxiv.org/html/2411.06037v3)，ICLR 2025，所读版本 2025-04-23 | 区分相关资料与足以回答问题的资料，结合充分性信号进行选择性回答。准确性与回答覆盖率存在权衡。 | 优先借鉴证据充分性检查；不能把模型自报信心直接当作正确率。 |
| [SPARKLE](https://aclanthology.org/2026.acl-long.1793.pdf)，ACL 2026，7 月 | 用独立代理控制检索；论文采用 3B 代理、知识三元组和 PPO 训练，不需要改动主回答模型。 | 借鉴控制层与回答模型解耦。当前数据和资源不足，不承诺复现其训练规模；固定规则仅作为原型与基线。 |
| [FinInteract](https://arxiv.org/html/2609.24002v1)，2026-09-21 预印本 | 通过默认解释与用户意图配对，评价澄清是否准确及是否用于后续回答；主要研究公司披露问题。数据规模和类别覆盖有限。 | 主动澄清已有先例。青盈应进一步检验个人信息缺失、知识不足、时效冲突与计算缺项的联合处理，而非只改写提示词。 |
| [Definition-Only RAG for Financial QA](https://aclanthology.org/2026.findings-emnlp.2448.pdf)，Findings of EMNLP 2026，10 月 | 定义检索的收益取决于模型与任务，术语知识信号不能可靠定位每题检索收益。实验限于所选词库与任务。 | 校园概念卡可作低成本基线；不能假定金融术语越多或检索越多越好。 |
| [EAGR](https://arxiv.org/pdf/2611.01910)，2026-11-01 预印本 | 在向量库元数据中建立隐式联系，依据累计证据扩展检索，无需单独图数据库。实验是通用多跳问答；有离线描述生成和在线多轮成本。 | 暂作扩展实验。先验证青盈是否有足够多必须跨文档回答的问题，再引入；不立刻建设复杂图系统。 |
| [CRITIQ](https://aclanthology.org/2025.acl-long.792.pdf)，ACL 2025 | 从少量人工成对偏好中提炼筛选准则，再使用更大规模机器标注训练评分器。验证领域是代码、数学与逻辑。 | 可借鉴筛选准则校准与可解释评分；约 30 对样本是论文设置，不能作为金融内容可靠筛选的样本保证。 |

补充参照：

- [When Is Additional Retrieval Worthwhile?](https://arxiv.org/html/2610.37358v1)，2026-10-27 预印本。其有限实验未确立回答正确性和忠实性的可靠提升，因此本项目必须同时检查检索、最终答案与真实调用成本，不能只报召回率。
- [Reliability Stress Testing of RAG Retrieval under Query-Relevant Corpus Poisoning](https://arxiv.org/html/2611.04264v1)，2026-11-03 预印本。研究检索准入层受污染影响；并未证明生成模型执行了恶意指令。青盈的自动筛选需同时测试异常材料漏放与正常材料误拒，不能用相关性得分代替可信性判断。

## 3. 拟研究的方法及原创边界

### 3.1 缺口分类与动作选择

将当前问题、授权的财务事实、用户已确认意图、检索证据及其日期地区、缺失字段、已消耗调用预算表示为可检查状态。模型可以提出候选字段和动作，但来源、账户授权及计算约束由程序执行。

动作集合：询问用户、检索公共资料、调用财务计算、组织有依据的回答、说明未能确定并暂缓。

| 缺口 | 正确动作示例 | 不允许的替代 |
| --- | --- | --- |
| 缺实际到账日或个人用途 | 问一个影响结论的具体问题，允许用户不回答 | 用网上“典型大学生”数据补全个人事实 |
| 缺费用定义或知识依据 | 检索适用地区和时间范围内的公共资料 | 把旧网页、不同地区规定混为当前依据 |
| 已有输入但缺方案差额 | 调用现有确定性工具并展示假设 | 模型自由生成金额并当作已计算结果 |
| 证据相互矛盾 | 定位冲突字段，核对版本或暂缓结论 | 根据多数转载或发布时间较新就裁定正确 |
| 信息足够 | 回答并提供核对依据 | 为增加 AI 存在感继续追问或检索 |

示例：“这笔分期每月看起来不多，可以买吗？”先区分用户是在问总成本、条款还是生活安排；缺合同费用则请用户提供，缺概念则检索，已获输入则计算。个人安排和客观知识不能混用一个检索结果填充。

拟检验的增量是：联合缺口表示和动作选择，相比固定检索、通用代理或只增加澄清提示，能否减少个人事实臆造、过期依据误用及无效交互，并保留有用回答覆盖率。它仍是待验证方法，不声称检索、澄清、计算或其简单组合为首创。

### 3.2 实现与学习路径

先以结构化模型输出和固定执行规则建立可运行基线；使用专家审核的情境及动作标注，训练或校准独立轻量动作选择器。可先使用可解释分类器，再与小模型微调比较；是否训练 PPO 等强化学习策略取决于数据与计算资源，不作为首版必需项。

模型输出保存字段、选择动作、证据编号和简短可核验理由，不收集或展示私有长推理过程。初始限制每轮最多两次公共资料检索、一次关键追问；具体预算在验证集调整。超时和模型不可用时沿用现有明确标识的回退方式。

用户可以纠正情境或关闭个人资料引用。低频返回时先确认旧资料是否仍适用；不能将几周前的余额视为当前余额。

## 5. 容量可确定：库存、配额、验证容量分开

### 5.1 可查询库存

统一文档主键、版本、片段、索引状态和发布状态。以当前快照统计：已采集、候选、已发布、有效可检索、隔离、过期、撤回、索引失败、历史版本。转载关联到同一内容族，版本和镜像不重复计为独立知识。

有效可检索文章 = 当前已发布且未撤回、满足适用条件、在当前索引快照完成索引的文档集合。采用不同适用范围查询时，应返回该范围的单独统计。

后台展示：当前文章数、唯一片段数、正文字符与字节、索引和归档占用、配额利用率、待处理量、最近成功更新时间及快照编号。支持导出包含来源、版本、筛选决定和索引状态的清单。生成摘要与原文证据片段分开统计。

### 5.2 首版拟配置额度

建议首版活跃库配置为最多 1,000 篇有效文档、20,000 个唯一证据片段；两个约束均需满足。这是待实现的管理额度，不是现有规模、当前硬件压测结论或必须填满的采集任务。

原文与历史归档另设磁盘字节配额，配额根据部署机器可用磁盘与备份方案确认，不以随意写出的 GB 数充当容量证明。达到任一配额后停止新内容晋级、进入容量等待队列并告警；保留现有内容，不自动删除高质量资料。重复、过时及无关内容不为凑数而入库。

首轮内容建设可先覆盖 100—300 篇合格资料，再按覆盖缺口增长。该区间只是建设目标，不能在未采集验收时写成已建规模。

### 5.3 工程容量验证

改用持久化全文与向量索引，统一查询发布快照，消除当前列表与教练入口的截断。技术可选择 PostgreSQL 全文检索与 pgvector，或独立持久化检索服务；选型需先在中文语料和本机环境比较，不在此宣称某组件已部署或保证性能。

按 100／500／1,000 篇及对应真实片段数做分级测试，覆盖短文、长文、更新、撤回、冷启动和并发查询。记录机器 CPU、内存、磁盘、模型版本、并发数、检索 P50/P95、错误率、增量索引时间及索引一致性。检索延时与大模型生成延时分开报告。通过验收的最大档位才称“已验证服务容量”。重复文本构造只验证负载，不冒充知识覆盖或检索质量证据。

## 6. 自动化筛选与发布

目标是无需人工逐篇录入，稳定低风险资料自动通过，异常交由管理员处理。自动筛选与自动发布是两个状态，筛选器自身未校准前先在影子模式记录决定。

流程：授权与来源配置 → 定时采集 → 正文与来源校验 → 精确及近重复处理 → 模型语义筛选 → 三路分流 → 增量索引 → 原子发布快照 → 定期复检。

### 6.1 硬条件，由程序执行

- 来源主机、栏目与跳转范围已配置；页面可访问不等于允许全文转载，须记录已确认的使用方式。
- 正文有效，无导航、验证页和模板污染；日期、适用地区、文档类型缺失时保留未知。
- 哈希处理完全重复，语义近重复用于候选聚类而非直接删改；金额、日期、否定词和适用范围变化强制保留版本并重新判断。
- 页面文字均视为资料，不允许其指令修改筛选策略、调用工具或取得用户数据。来源等级取自系统配置，不信任正文自称“官方”。
- 文件、调用、时间及容量有预算；失败重试设上限，保留旧发布版本。

### 6.2 模型辅助语义筛选

输出结构化字段：主题、人群、地区、发布日期与生效时间（未知分开）、核心主张及原文位置、知识类型、校园相关性、可理解性、商业推广倾向、可能冲突、建议处理方式与证据。

抽取、相关性判断和事实核实分开：模型能发现可疑内容，不意味着能凭内部知识证明所有事实正确。模型输出的证据位置由程序验证；发布规则采用硬门槛与经标注校准的分类结果，不能让高相关分抵消来源不明、时效冲突或使用权限未确认。

借鉴 CRITIQ，先组织教师对一批真实候选做成对质量评价和可发布／需复核／不适用标注，再在独立样本验证阈值。少量偏好样本用于制定标准，不足以独立证明自动发布安全。自动生成标签可辅助扩大训练集，但测试真值不能全部来自同一模型。

### 6.3 分流

| 分支 | 条件与行为 |
| --- | --- |
| 自动通过 | 已配置来源和内容类别、使用方式明确、适用信息完整、无检测到的冲突、质量门槛通过且筛选器已通过相应类别验证。发布源文证据；AI 摘要明确为派生内容并单独验证。 |
| 自动隔离待复核 | 地区或日期不明、政策费用发生变化、相似版本关键数字不同、模型意见冲突、出现可疑指令或无法确认支撑关系。只显示异常队列。 |
| 自动排除 | 重复、空壳、明显无关、未获允许的来源或不符合已配置准入政策；记录理由，支持纠错。 |

不能保证全自动零误判。将人工工作集中在来源初始配置、校准样本、异常和定期抽检；对已验证类别逐步自动发布，模型或来源大幅变更时重新验证。抽检同时包括通过与拒绝两侧，防止只追求通过率而漏掉有用内容。

所有决定记录：文档与版本 ID、原文指纹、规则及模型版本、证据位置、决定、时间、操作者类型与索引快照。发布、撤回与缓存失效同步；索引失败不计为已可检索，发布切换失败保留旧快照。

服务常驻才可定时更新；可在已有后台工作进程运行，服务器部署需配置持续运行、重试与运行状态监测。自动化不等于只在用户打开页面时尝试抓取。

## 7. 验证研究创新，而非只验证代码能运行

拟先构建约 200 个经人工审核的校园问题，用于开发与先导评估；具体规模按误差精度和各类别数量调整。覆盖资料充分、个人信息缺失、证据缺失、时效地区冲突、数值工具输入缺项与不需要更多检索等情形。按问题家族、来源和版本划分开发／验证／测试，模板变体不得跨集合泄漏。

比较：当前固定混合检索、加入通用澄清提示的基线、拟议动作选择方法。冻结回答模型、资料快照与预算，分别移除缺口分类、时效约束、成本控制，检验每项设计的增量。

主要技术指标：动作选择正确率、个人事实臆造率、无依据或过期引用率、引用支撑程度、完整任务成功率；同时报告有效回答覆盖率、错误拒答、追问轮数、调用次数、真实 token 成本与时延。仅用模型评审不作为最终结论，关键错误由人工盲审。

筛选评价：通过资料的合格比例、合格资料被漏掉的比例、异常漏放率、各类别置信区间、自动通过占比与人工处理时间。阈值只在验证集调整，不能看到测试结果后修改再汇报原测试分数。

后续学生试用另行检验自主决策、知识迁移和负担。技术指标改善不自动等于财商意识提升，模拟用户也不能替代真实学生。

## 8. 与当前代码对接及推进顺序

1. `knowledge_updates.py`：保留原文版本与发布记录，增加筛选决定、准入策略、异常队列与容量预约；先影子运行，避免默认改变所有已发布资料。
2. `admin_service.py` 与知识接口：统一文档查询和计数，添加分页、范围与快照参数，移除静默截断，后台显示容量与筛选状态。
3. `knowledge_retriever.py`：持久化增量索引；证据充分性、地区和时间状态进入返回结果，索引状态与库存统计一致。
4. `coach_routes.py`、`coach_tools.py`：接入缺口识别和动作选择，按授权读取个人信息，复用财务工具及现有回复校验。
5. 验证集校准筛选器，再对明确类别启用自动发布；保留策略开关、影子比较、旧快照与撤回操作。
6. 完成基线、消融、容量与更新一致性测试后，按实际结果更新申报书中的已完成部分。

首轮最有价值的交付是：真实容量报表、可审计的自动筛选原型、可比较的缺口感知动作选择器，以及独立评测材料。当前仅完成论文调研、代码核对和容量只读审计。
