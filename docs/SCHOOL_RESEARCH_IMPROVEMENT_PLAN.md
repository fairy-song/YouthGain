# 青盈学校端与隐私保护研究改进方案

方案日期：2026-10-07。本文为待实施设计，新增能力均未上线。

实施更新：首个里程碑现已完成代码实现，详见 [使用与实现说明](SCHOOL_RESEARCH_MILESTONE.md)。下文仍保留总体规划；联邦能力、群体PCA及真实试点评估尚未完成。

## 1. 目标与现状

学生端继续提供精确记账、预算、个人消费模式探索和 AI 教练；学校研究端只访问经过隐私保护的群体统计，用于设计金融教育内容和研究参与者的消费变化。

现有 React + Flask 架构可以继续使用。后端已支持账号认证、个人消费记录、统计和个人 PCA，但角色目前主要为 user/admin，缺少学校研究身份、项目授权、研究同意管理和差分隐私发布流程。已有管理员入口不能直接作为学校研究端。

第一阶段采用“可信青盈后端 + 学生级中央差分隐私”。保护对象是学校研究者获得的发布结果；可信后端及其授权运维仍可能接触明细，不能宣称服务器看不到原始账单。正式试点前还需按学校要求完成研究审批、数据治理和运行环境验收；本方案不是对具体研究合法性的结论。

## 2. 第一版功能范围

| 角色 | 新增功能 | 数据范围 |
| --- | --- | --- |
| 学生 | 查看研究说明、主动加入、退出、查看贡献周期 | 本人的同意状态和个人数据 |
| 学校研究者 | 群体月度看板、固定指标、趋势比较、报告导出 | 已发布的差分隐私快照 |
| 研究项目管理者 | 建立项目、配置指标和发布计划、绑定研究者、查看预算和审计 | 项目配置和发布状态 |

研究身份由服务端授予并绑定学校、项目和有效期。每个请求检查具体项目权限，不能仅检查“是否为研究者”；普通学生、其他学校的研究者不能访问项目结果。研究者不继承现有 admin 权限，不获得用户详情、账单、商户、备注或 AI 对话接口。

学生参加研究与授权 AI 教练分开设置。未参与不影响记账、学习和个人分析。研究说明应列出目的、指标、周期、接收方、保存期限和退出方式。

## 3. 研究指标及统计口径

先发布三个可解释指标，不收集新的消费明细：

1. 月度已记录支出区间分布：采用预先公布的固定区间，每名学生每月只进入一个区间。名称明确为“已记录支出”，不能当作全部实际支出。
2. 类别支出占比：先计算每名参与学生的类别占比向量，再研究群体平均占比。固定类别及“其他”桶；向量非负且总和不超过 1。该结果是学生平均占比，不是全部消费金额汇总后的占比，两者必须区分。
3. 预算比较分布：仅在预算资料有效时，对“已记录支出与预算的比值”进行预先分箱。资料缺失、无预算或无记录采用明确的状态桶，不能默认等于零消费。

第一版按项目、自然月发布，不开放自由组合院系、班级、性别、日期或金额条件。研究群体及类别在发布前确定；群体变更、增加指标和重发均作为新的发布操作审查。

数据口径写入快照：统计月份、记录截止时间、指标版本、参与规则和适用限制。参与者是自主加入且主动记账的学生，存在选择偏差和漏记；结果不直接代表全校学生，也不证明教育干预产生了因果效果。

## 4. 差分隐私发布机制

保护单位为一个学生在项目研究范围内的全部贡献，明确采用增加或移除一名学生的邻接定义。每月只允许一份贡献，跨月和跨指标发布统一计算累计隐私损失；不能把学生级保护偷换为单笔交易保护。

发布流程：

学生研究同意 → 按预定规则提取月度特征 → 限制每名学生的贡献 → 聚合并使用审查过的 DP 机制 → 原子扣减预算并保存快照 → 学校端查询快照。

核心要求：

- 用固定区间的直方图、限定范数的向量等明确贡献边界，再根据邻接定义推导敏感度。人数、分母、缺失状态、群体比较和趋势都纳入隐私分析，不能只给总额加噪声。
- 使用经过验证的差分隐私实现和安全随机源；不自制“随机扰动就是 DP”的算法。生产参数在威胁模型、发布频次和效用实验确定后再批准，不先承诺某个 epsilon 就足够安全。
- 每个项目记录预算账本；涉及同一批学生的多个项目还要有统一的组合预算策略。更换研究者、账号、导出格式或学校不能重置已消耗预算。
- 发布采用幂等标识、并发控制和事务。相同快照的刷新、查看、下载都复用结果，不重新采样；重算或更换群体必须重新核算预算。
- 预算不足时拒绝新增发布，历史快照仍可按授权查看。原始数据更新不自动触发额外发布。
- 小群体限制作为辅助措施，门槛判断采用公开已知的群体规模，或已计入预算的受保护人数；不通过“显示/隐藏图表”泄露精确私有参与人数。
- 负数修正、比例归一化等只对 DP 输出做后处理，保留处理说明。用区间或误差提示避免过度解读小群体结果。

这一设计遵循 DP 需要明确保护单位、威胁模型及实现边界的原则，技术评审参考 [NIST SP 800-226](https://csrc.nist.gov/pubs/sp/800/226/final)。

## 5. 退出、保存和导出

退出后停止新的研究贡献，删除或按项目规则到期清除尚未发布的研究特征。已经发布的群体结果不能恢复成“移除该学生后的同一结果”，也不能承诺从已下载报告中追回其统计影响。若重新发布结果，按新发布处理预算。

研究贡献与个人账本分开保存，退出研究不删除个人账本。项目规定原始研究特征、快照和审计记录的保存期限及访问权限；学校端只能导出与看板一致的受保护快照，不额外附带精确样本数或个人记录。

学校端报告生成优先采用固定文字模板。如果引入 AI 报告助手，仅提供已发布快照及口径说明；不复用学生端能读取个人资料的教练接口。

## 6. 现有 PCA 和联邦能力的定位

个人 PCA 继续服务学生自己的消费探索，不直接作为学校端的数据上传接口，也不对学生进行冲动、财商或心理评分。

群体 PCA 放在后续研究阶段：先确定固定特征与标准化尺度、限制每名学生贡献，对均值及二阶矩等统计量实施经审查的隐私机制，再由受保护统计求主成分。所有依赖私有数据的特征筛选、尺度估计和模型选择也要纳入预算。简单汇总个人 PCA 或对已有主成分加随机噪声不能视为完整 DP PCA。只有在解释稳定性和统计效用评估通过后才发布。

第二阶段可做联邦分析：月度特征在学生设备上计算，通过安全聚合接收群体结果，并结合与信任模型相匹配的 DP 机制。当前数据仍集中存储，必须改造实际的数据链路，不能仅把函数命名为“联邦”就声称原始数据留在设备。协议还需处理重复参与、虚假设备、掉线、最小聚合规模及跨轮预算。

联邦学习用于第三阶段的共同模型训练，例如消费类别识别。先建立普通模型基线，确认联邦方案确有价值，再验证安全聚合、学生级 DP、通信开销、分类准确率与跨学校泛化。基础群体统计采用联邦分析更直接，参考 [Google Research 的联邦分析说明](https://research.google/blog/federated-analytics-collaborative-data-science-without-data-collection/)。

## 7. 开发拆分

以下名称为建议的新模块与结构，不代表已经创建或上线。

| 模块 | 工作 |
| --- | --- |
| 身份和项目授权 | 新增 research 身份、学校/项目绑定、独立鉴权；隔离现有 admin 接口 |
| 研究同意管理 | 记录同意版本、加入时间、退出时间、范围和生效周期 |
| research_feature_service | 从已授权学生记录构造限定贡献的月度特征 |
| privacy_release_service | 对接经过验证的 DP 机制、敏感度及参数配置 |
| privacy_budget_store | 统一预算账本、发布事务、幂等处理和审计 |
| research_routes | 读取项目配置和既有快照；学校端不提供实时原始查询接口 |
| 学生研究页面 | 研究说明、参与/退出、贡献状态 |
| 学校研究页面 | 固定月度图表、统计口径、误差说明、快照导出 |

建议结构包括 research_projects、research_memberships、research_consents、research_contributions、privacy_budget_ledger、research_releases。内部 UID 与研究贡献的映射只在受控后端使用，不出现在学校响应或导出中；哈希 UID 本身不等于匿名化。

## 8. 实施顺序与交付

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A：方案与演示 | 固定研究口径、角色模型、模拟数据看板 | 可以完整演示，但显著标明模拟数据 |
| B：DP 原型 | 三项指标、贡献限制、快照和预算机制 | 数学设计、误差实验、权限及并发检查通过 |
| C：受控试点 | 同意/退出、保留期限、实际项目授权和运行配置 | 项目审批与数据治理完成，记录质量可说明 |
| D：分布式扩展 | 安全聚合联邦分析；按需要增加联邦学习 | 与中央方案比较隐私边界、效用、成本和失败处理 |

先完成 A、B，再决定 C、D。工期需在研究指标、存储引擎和试点条件明确后估算。

## 9. 验收与研究评估

- 权限：学生、研究者、其他学校和平台管理员分别验证项目边界，研究者无法调用用户详情接口。生产环境禁止开发认证绕过。
- 同意：未同意者不贡献；退出后不再进入新发布；研究加入与 AI 教练授权互不影响。
- 发布：重复点击和下载不产生新噪声或新增预算；并发请求只生成一次快照；失败不会产生无预算记录的外泄结果。
- 隐私：贡献边界、保护单位、敏感度和组合记账由设计评审确认；通过攻击场景检查和实现审查验证，不能单凭测试通过就宣称正式 DP 保证。
- 统计：模拟不同人数、漏记比例及异常值，测量分布误差、均值误差和趋势保持情况；正式数据的精确对照仅在受控后端供授权评估使用。
- 页面：显示数据月份、指标版本、受保护统计及限制；不会把噪声结果解释为个人风险或精确贫困情况。
- 效果：群体消费变化与教学效果分开评价。若研究干预效果，需要事先确定研究设计、对照和分析方法，不能只凭看板趋势归因。

推荐首个里程碑：独立学校研究角色、学生研究同意页、三项固定月度指标、学生级 DP 发布、预算账本、缓存快照和受保护导出。联邦学习及群体 PCA 保留为后续研究扩展。
