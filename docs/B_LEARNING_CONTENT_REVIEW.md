# 阶段 B：学习题库审核与发布

青盈当前有 32 道原创试用题，状态均为 `pilot`；其中 24 道属于八组多步情境。它们可用于当前产品试用，但尚无独立金融教育专家或学生试测的正式审核记录，不能称为已验证题库。系统当前没有 `approved` 题。

## 状态与发布门槛

| 状态 | 用途 | 是否进入个人学习推荐 |
| --- | --- | --- |
| `draft` | 编写、修改、复核中的题 | 否；接口也拒绝提交答案 |
| `pilot` | 青盈原创试用题，便于小范围试用 | 是；必须有来源说明，并在题库中保留试用标记 |
| `approved` | 完成内容复核的正式题 | 是；必须有来源链接、审核人、审核日期与来源说明 |
| `withdrawn` | 发现错误、过时或不适合继续使用 | 否；历史答题记录保留其当时的内容版本 |

题目定义在 `backend/app/services/adaptive_learning.py` 与 `backend/app/services/learning_question_bank.py`。新增题默认是 `draft`。每题保存知识点、适用消费情境标签、难度、前置步骤、预计时间、来源说明、内容版本和审核状态。提交记录另保存题目内容版本、知识点与当时的审核状态，以便以后解释旧答案。启动时的 `audit_bank()` 会检查元数据、选项答案和步骤链；它只检查结构，不能替代人工内容判断。

## 人工审核顺序

1. 编辑先核对题目与大学生日常情境是否贴近，题面是否清楚，是否把“少花钱”错误地写成唯一正确选择；开放题不能按关键词武断判对。
2. 独立复算金额题，包括手续费、退款、时间范围、每期与总额；检查错误答案和部分正确反馈是否与题设一致。遇到法律、金融产品或安全信息，还要核对适用地区和资料时效。
3. 核对来源链接，确认它支持知识点或题型设计；青盈自编数字情境需明确标为原创，不把参考框架表述成对具体数字的背书。
4. 复核人填写 `reviewed_by`、`reviewed_at`（`YYYY-MM-DD`）和 `reference`，增加 `content_version` 后将题目标为 `approved`。内容变化后重新进入 `draft`，重新审核后才正式发布；发现问题立即标记 `withdrawn`。
5. 运行题库校验、金额题复算、推荐与账户隔离测试，再用少量学生试测阅读负担、误解和反馈语气。记录修改原因与版本，尤其不要仅凭答题完成率宣称学习有效。

当前审核信息维护在代码中；没有后台审核工作流。未来题量明显增加时，再考虑持久化审核记录与双人复核界面。当前可在服务端运行 `python -c "from app.services.adaptive_learning import audit_bank; print(audit_bank())"` 查看状态计数。

现也可在项目根目录运行 `python backend/evaluation/content_audit.py` 查看状态，或加 `--csv docs/B_CONTENT_AUDIT_WORKSHEET.csv` 导出逐题审核工作表。工作表含标准答案，只用于内部人工审核，已排除在公开代码仓库之外；填写它不会自动把题目改为 `approved`。试用题在学习卡上标为“试用题”。B、C、D 后续运行边界见[学习评估说明](./B_C_D_LEARNING_EVALUATION.md)。

## 推荐与解释的边界

系统仅用本人近期已记录消费形成情境线索，来源会标为交易类别、交易回看、近期计划或个人复盘，并带有规则版本；它不从金额、商户或备注推断能力。答题证据独立按知识点记录，来源为情境题，也带有规则版本。账本读取失败或可能被截断时，消费线索为空，仍可按问卷、本人选择及答题记录学习。推荐只显示一题、一条主要原因；到期复习参与排序，答题后给短反馈与一条可选的小尝试。当前复习同一道题只是提醒，不算新的迁移能力证据。
