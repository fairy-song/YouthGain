# 青盈新用户体验减负方案

## 结论与范围

本轮实际操作表明，主要门槛来自任务选择、资料准备、页面跳转和结果理解。优先把“打开—完成一件小事—得到可理解的反馈”缩短，再决定需要什么帮助。已撤销的v1.1前置教学不恢复。

本文件记录最初走查与分阶段方案。用户随后授权实施P0，v1.2的实际完成范围见[实施记录](v1.2首笔记账减负实施记录.md)；P1、P2及游客草稿衔接仍为拟议工作，不代表已获得新用户可用性或教育效果结论。

## 实际体验记录

2026年11月8日在本地运行环境，通过实际浏览器操作检查欢迎页、免登录试算、登录、首页、账本、教练入口、学习及资料设置。使用已有演示身份查看历史界面，并用独立本地测试身份检查空状态和首笔保存；在后者保留1笔12.50元、明确标注“体验检验、非真实消费”的示例。没有修改原有演示账单、真实用户资料或保存资料设置，没有发送真实财务资料给外部AI。

这是产品人员的启发式走查，不是招募真实新用户的可用性研究；未做计时或手机尺寸验证，不报告完成率、耗时优势或移动端结论。表中只将实际可见现象列为证据，原因和改法属于设计判断。

| 实际操作 | 可见现象 | 对使用的影响 |
| --- | --- | --- |
| 首页点击“免登录试一笔” | 初始即出现可用资金、下次到账、每日估计、购买金额、购买日期、到账延迟及必要开支等条件 | “一笔消费”承诺与实际资金规划工作量不匹配 |
| 点击“用示例试试”后试算 | 需比较原计划与调整后的到账日、剩余或缺口、首次不足日，并理解每日开销及预留口径 | 第一次体验就要求理解模型假设，钱币反馈在结果后还要展开 |
| 空账号进入首页 | 消费观察、可用剩余、未来开支、分期计算题、音频推荐同时出现 | 有多条互不依赖的路线，用户难判断现在该做什么 |
| 空账本填写第一笔 | 收支类型、金额、类别、日期、商户、时段、消费内容和备注均直接显示；旁边并列补记、支出导入、收款导入和语音 | 可选字段仍占据注意力，入口之间的区别需要用户判断 |
| 保存12.50元示例支出 | 钱币确实展示且账单保存成功；资金未核对时仍展示“本月可用剩余 -12.50（估算）” | 局部记录计算容易被当作实际余额不足；问题首先是口径与完整性表达，尚未核对计算根因 |
| 查看保存提示 | 出现“理财成长 → 我的资料”，实际主导航为“今天、账本、学习、我的” | 提示要求寻找已经不存在的路径，且无直接操作入口 |
| 去“我的”补资料 | 财务设置排在财务卡片、成长统计、问卷和研究入口之后；展开出现余额、必要开支、应急预留、收入、到账日、时区、主题和规则 | 为了一个试算条件，需要进入一整张资料表；信息索取早于当前任务所需 |
| 同一账户跨页看资金 | 账本显示-12.50，“我的”显示-13；同时“上月结转”仍未确认 | 展示精度及未知状态不一致，增加解释成本 |
| 推荐内容进入教练 | 输入框预填一段包含“如果未获取全文请明确说明、不要编造”等系统约束的长提示词 | 用户需要阅读和理解内部指令，而非直接表达自己的问题 |
| 点击“学习” | 默认进入多步情境计算；“消费选择、每周复盘、知识库”等收在“其他功能”中 | 抽象栏目名与用户“想买东西、回看花费”的目标对应不直接 |
| 去“我的” | 零次记录的用户已显示“当前财务认知等级：财务新手”及多项零进度 | 活跃度、练习记录和财务能力混合，可能产生无依据的评价感 |

## 建议的第一次体验

入口说明一句具体收益，例如“把花费变成看得见的钱”。一个主要入口“看看一笔花费”，进入即可改示例金额并看到钱币；不先填写余额、收入或到账日期。可选的高级消费试算保留在“想知道会不会影响生活费？”之后，名字明确为“生活费试算”。

游客数据是试用草稿，有显著示例标识和清空入口。需要保存时再登录；登录前说明保存范围，登录后确认保存一次，不自动批量写入，不丢失刚才的输入。登录和注册不得增加测评或财务资料门槛。这一流程必须先核对现有认证与草稿机制，不能靠把演示账单直接写到账户来实现。

学生首页按资料状态展示：

- **还没有记录**：直接呈现紧凑的记账入口，金额、类别为主要输入；日期默认今天且可改。导入作为明确的次要入口，其余字段由“补充详情”展开。
- **已经有记录**：先看已记录花费和近期记录，给出一个适合当前上下文的下一步。未来开支有实际记录时再突出提醒；其余能力可以通过固定导航随时到达。
- **隔几天回来**：回看最近记录和上次操作，不要求补齐每天、不展示未记录期间的推算消费。允许只导入一段记录、看完就离开。

首页不是按使用次数“解锁”功能，也不隐藏用户已知入口；新旧用户都应能随时找到完整工具。初期优先将可选区域折叠、统一入口，而非引入另一套权限或成长等级系统。

## 改造优先级与验收

### P0 先恢复可信和顺畅

1. **正确呈现未知资金**：保留已知支出12.50元，未确认余额或结转时不将局部估算突出为可花余额；展示“资金资料待核对”。明确记账结余与真实可用资金，统一账本、首页、资料页的完整性判断与金额精度。验收必须覆盖无记录、只记支出、只记收入、已核对资金、退款与储蓄，避免只是隐藏负数或一律当零。
2. **修复错误指路**：清理旧“理财成长”路径；把补条件改为可直接点击、返回后保留原任务的操作。缺哪项就在试算附近补哪项，保持明确保存反馈，不自动修改用户财务资料。
3. **精简首笔记录**：金额和类别主展示，日期清楚可改；商户、时段、备注、消费想法收进详情。默认“记支出”，收入仍可明确切换。导入、补记、语音放到“更多记账方式”，保留可发现的入口及原有校验。

这一批先消除真实摩擦；不同时重构推荐、模型和整套导航。

### P1 让首页围绕当前任务组织

4. **收拢首页选择**：保留一个主要操作和清楚的消费反馈，弱化多个同等强调的模块。资料不完整时显示下一步需要确认什么，不堆公式、零值和警告。精确口径通过邻近说明展开，不能移走关键限制。
5. **分开两种试用**：钱币感知只需一个金额；生活费规划才询问可用资金、到账日和必要开支。高级试算先显示最少必要条件，其他情境按需展开，先提供与数据相称的结论再展示明细。
6. **教练继承任务**：从账单或推荐进入时，以短摘要标明“围绕这笔记录提问”或“了解这期主题”，用户只需选问题或补一句话。模型约束移到服务端；个人数据发送仍需明确授权，不因减少点击而暗中开启。

### P2 服务低频使用

7. **只在当前任务索取资料**：看消费不要求补收入；做规划才补资金条件；时区默认本机或既有设置，详细偏好放设置页。所有默认值需要标明可修改，不推测用户真实收入。
8. **学习回到生活问题**：优先提供“这笔消费怎么看”“下周先留哪笔钱”等真实任务入口，练习题保留为主动选择；不以算对题、打卡数或使用次数给财务能力下结论。
9. **反馈可停、可改、可继续**：保存后就地确认和短钱币反馈，不追加必填复盘或强制设置。允许查看、修改和继续记录。先核对现有编辑与删除机制，再设计撤销，不能用不可靠的前端假撤销承诺数据恢复。

## 视觉与动效

保留暖白和深绿，靠字号、对齐、留白及一个清楚的主要按钮形成层次；减少多个完整模块同时争夺注意力。钱币反馈解释“这笔记录的金额”，避免撒币庆祝消费或使用户等待动画结束。移动端优先单手完成金额输入和保存，关键操作不被键盘遮住；尊重减弱动效。实际尺寸、输入法、滚动和焦点需要在实施阶段验收，本轮未验证。

## 如何决定方案是否更好

先找5名未使用过青盈的同学进行探索性走查，不讲解页面，给三个任务：记录一笔支出并确认成功、看懂自己能确定和不能确定的资金信息、离开后回来找到记录。允许用虚构账单，不要求真实财务资料。

观察是否独立完成、错误路径、需要解释的位置、填写字段数及愿不愿再次使用。首笔记录以60秒内独立完成作为设计目标而非现有结果；金额理解优先于速度，不能靠省略必要限制换取短耗时。另检查拒绝补资料、弱网、登录失败、草稿恢复、权限隔离及金额边界。先完成小批低风险改造并对比，再决定是否扩大；不把5人走查结果当教育效果或总体成功率证明。

## 实施边界

最初走查仅形成方案，后经用户授权以v1.2实施P0，不重新发布v1.1。保留v1.0回退点，每批改造独立开关或小提交，按实际变更运行测试、桌面与手机验收及构建。方案中的草稿登录衔接、上下文摘要、撤销等均为拟议工作，不是当前已具备功能。
