# 手动收支接口

`POST /api/decision/transactions`，使用现有身份认证。金额为正数，收支方向由 `transaction_type` 指定，省略时仍保存为支出。

```json
{
  "transaction_type": "income",
  "amount": 200,
  "category": "兼职",
  "date": "2026-10-14",
  "receipt_kind": "other_income",
  "merchant": "付款方",
  "items": "兼职结算",
  "note": "",
  "hour": 15
}
```

| 字段 | 规则 |
| --- | --- |
| `transaction_type` | `expense`（默认）或 `income` |
| `amount` | 大于 0、不超过 100000000 的有限数字；布尔值无效 |
| `category` | 必填，最多 64 字；支出类别或收入来源 |
| `date` | 必填，YYYY-MM-DD；收入不能使用未来日期 |
| `receipt_kind` | 收入支持 `red_packet`、`external_transfer`、`other_income`（默认）；本人内部转账不能记为收入 |
| `merchant` / `items` / `note` | 可选文字，分别最多 128 / 1000 / 255 字 |
| `hour` | 可选，0–23 |
| `planned` / `purpose` | 只用于支出；收入保存时清空 |

成功返回 HTTP 201：`{"status":"success","message":"收支记录已保存","data":{...}}`，`data` 包含生成的 `id`、`timestamp`、收支类型和来源字段。参数无效返回 400；保存失败返回 500。

`GET /api/decision/transactions` 保持原响应结构；手动收入计入 `monthly_cashflow.income`、相应的 `income_breakdown` 和 `funds.available_remaining_month`。不会进入消费分析、支出分类图或退款原交易候选。本人内部转账不计入收支。已有账单导入接口不变。

可用剩余继续遵循：上月结转结余 + 本月实际收入 − 本月净支出 − 本月净储蓄划拨。储蓄锁定总额作为独立特征。旧余额确认缺少实际收入核对基准且已有收入记录时，需要重新确认一次余额，避免重复加收入；新确认会保存 `balance_recorded_income_total`，后续估算只加入确认后的收入差额。

MySQL 启动检查缺失的 `transaction_type` 和 `receipt_kind` 列后自动补齐；历史行默认 `expense`，迁移不覆盖既有金额。开发存储及 Firestore 直接保存这两个字段。
