# 青盈三端端到端体验审查

审查版本 `7ae6313` · 2026-11-06

## 核心结论

问题集中在任务衔接。首页承诺「开始体验」，实际先做问卷；学生登录默认进入账本，账本又将未完成问卷的人送回问卷。用户从收藏的地址、首页按钮或别人的链接进入同一功能，会遇到不同的登录与返回路径。即使单个页面能用，串起来也会让人怀疑是不是没登上。

第一轮应优先修登录、注册与回到原任务，再调整首页视觉。将「第一次能完成一件事」作为验收目标。

## 方法和范围

- 按访客、学生、管理员和老师分别记录「进入、登录、做事、遇错、恢复」，以任务是否完成作为判断依据。参考 [GOV.UK 的完整用户任务走查](https://www.gov.uk/service-manual/design/map-a-users-whole-problem)。
- 用干净浏览器会话、模拟账号和接口，在 390px、1280px 两种宽度重现入口和权限相关问题。代码走查覆盖账本及账单导入、未来开支、试算、学习、AI 教练、我的、管理员内容及账号管理、学校研究、导出和验证邮箱。
- 下表标明「浏览器复现」「代码走查」或「设计判断」。模拟会话不能替代真实 Firebase、邮件送达、正式学校账号、不同浏览器的密码管理器及辅助技术验收。此次审查没有操作真实账单、内容或授权。

## 优先问题与验收条件

P1 指任务被拦、用户回不到原任务，或账号边界不清。P2 指信息或操作反馈不足，容易增加试错。

| P2-11 | 未来开支的「已处理」只改变计划状态，真实付款还需另外记账。虽有文字说明，任务仍要跨两个入口完成。 | 代码走查，[未来开支](../src/components/UpcomingExpenses.js)。 | 标记后提供「去记这笔支出」入口并带入用户可核对的信息；同一开支避免重复计入。 |

## 建议的主路径

本轮实施计划

1. 稳定学生登录和注册页面，统一入口与安全的回跳规则。默认进入「今天」，从受限任务进入时保留页面和查询参数，学校和管理员入口保持角色边界。
2. 取消账本前的问卷门槛。问卷改为可自愿完成的体验，草稿按账号隔离，提交前确认是用户主动选择保存。
3. 复用现有生活费试算开放访客体验，接入账号恢复，在无邮件服务的本地演示环境说明可用方式。
4. 跑学生、学校、管理员三条浏览器路径，覆盖首次提交、注册回跳、权限拒绝和移动视口，并把实际通过情况记在本文。

| 人群 | 推荐路径 |
| --- | --- |
| 学生第一次来 | 首页 → 试一笔生活费示例 → 看懂结果 → 想记账时登录或注册 → 打开账本 |
| 学生回来用 | 首页 → 学生登录 → 今天；从账本、复盘或教练链接来时，登录后回原处 |
| 管理员 | 管理入口或审核链接 → 身份核验 → 原审核任务或管理概览 → 确认处理结果 |
| 老师 | 学校端 → 演示或登录 → 需要时验证邮箱 → 查看获授权项目与月报；无授权时能核对邮箱并刷新 |

## 本轮修改与边界

- **P1-01 至 P1-04**　普通学生登录默认到「今天」。账本可直接使用，深链接经登录、注册后保留标签。管理员回到原审核任务，普通账号进入管理入口时可返回学生端。
- **P1-05 至 P1-06**　三端登录接入正式认证的密码重置，保留登录入口和待办任务。本地模拟认证仍显示测试登录说明。问卷草稿按账号读取，登出清理，匿名问卷只凭本次明确的保存操作绑定。旧草稿缺少归属信息，下次读取时清除。
- **P2-07 至 P2-12**　首页把试算、记账和问卷拆为三条路径。访客试算在当前页面计算，登录后可从账本开始。学生端试算可以带入消费金额，由用户决定是否保存选择。问卷可回到最后一题。首页各模块、学习与复盘账目分开读取。已处理开支可以带入记账表单，现有草稿先征求是否替换；跨设备防重复入账仍需账单与计划建立持久关联。
- **P2-13 至 P2-16**　账单导入区分写入结果和列表刷新，管理员概览支持分别恢复统计与用户列表。学校端提供发布和授权清单，无有效授权时可核对邮箱、切换账号或看演示。演示月报、访客试算不依赖全站服务检查。管理端暂未增加待办优先级，学校端对无授权账号统一说明可公开的下一步。

真实环境仍需确认密码邮件投递与浏览器密码管理器自动填充。发布前可分别请首次使用者完成「记一笔」「审一条内容」「找一份月报」。

## 回归验收

- 234 项前端测试通过，生产构建通过。
- 使用模拟账号与接口，在 390 像素和 1280 像素视口各通过 9 条浏览器场景，包括第一次按回车登录、学生实际提交一笔模拟账单、注册回到每周复盘、管理员回到知识审核、普通账号被拒、老师打开获授权月报、离线看演示、明确保存问卷，以及独立恢复读取。
- 本机预览已确认显示新版首页和学校登录页。密码找回用模拟邮件服务验证界面和回跳。浏览器回归未提交真实账单或发送真实邮件。

## 三端独立实施计划

1. 公开首页保留学生、学校、管理三个入口。各端的登录页、导航和业务页面只提供本端操作，学生研究报名留在学生端。
2. 将建项目、发布和授权移到管理员端。学校端继续通过既有服务端授权查看月报。
3. 登录会话限于发起登录的端和浏览器标签。直接输入其他端网址时要求在该端登录，同一标签刷新保留当前端登录。
4. 用三类模拟账号测试端内跳转、跨端直链、错误角色拒绝、刷新和多个标签的并行登录。

三端入口保留在公开首页。学生从「我的」参与研究，旧报名链接自动转到学生端的新地址。学校端查看获授权的月报，建项目、发布与授权在管理端的「研究项目管理」完成。管理员账号从管理入口登录；手动打开其他端的受保护链接时，该端要求单独登录。同一标签刷新保留当前登录，不同标签可分别使用不同账号。旧登录状态切换到新版本后需重新登录一次。

238 项前端测试与生产构建通过。手机和桌面各通过 11 条模拟浏览器场景，覆盖三端导航、跨端直链、错误身份、各端刷新，以及一个标签退出后另一个标签仍能工作。正式 Firebase 账号尚未实测。
