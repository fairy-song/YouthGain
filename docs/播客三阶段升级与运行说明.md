# 播客三阶段升级与运行说明

本次修改集中在每日播客内容供给。新增公开 RSS/Atom 增量采集、AI 辅助整理、多源发现和 WebSub 更新通知，继续使用现有候选筛选、财务情境与 HSTU 精排。代码具备完整处理路径；外部账号、来源许可和真实服务联调仍依赖部署环境。目录覆盖率、发现延迟及推荐效果均不能由离线测试推定。

## 使用入口

管理员登录后进入 `/admin/podcasts` 的“内容发现与自动更新”。

1. 在服务端 `PODCAST_RSS_ALLOWED_HOSTS` 中核准实际来源域名；多个用英文逗号分隔。重定向目标域名也须核准。重启后端和独立工作进程以加载配置。
2. 添加公开 RSS 地址，确认许可，点击“保存来源并采集”。后台依次采集新单集、整理主题和学习要点。
3. 在单集目录查看待审核记录与整理依据。资料不足或存在异常时，编辑补充主题、简介、质量评分等资料，再审核发布。
4. 已发布单集自动进入原有候选筛选和 HSTU 排序。新内容不改动当天已保存的推荐；撤回、资料变更及停用来源立即阻止相关单集继续展示。

初始默认人工终审。可信来源可单独开启“完整资料通过规则检查后自动发布”；简介不足、语言不明、相似单集、推广/注入信号、AI 生成整理均进入人工审核。自动发布只判断元数据资料与配置规则，不等于已核验音频事实或审听完整节目。

## 三阶段实现

### 第一阶段：持续更新

- 增加 `podcast_sources`、`podcast_shows`、`podcast_episode_keys`、`podcast_jobs` 等表，与现有 SQLite 账本共用 `PODCAST_DB_PATH`。
- 保留 `programs` 作为兼容的单集投影，旧单集 ID、每日推荐和反馈不变；旧节目主页归并成节目，旧 RSS 配置由工作进程逐步登记为来源。
- RSS GUID 在来源内唯一，缺少 GUID 使用规范化单集页面 URL；来源允许收录多期，订阅源中旧一期消失不代表删除。
- ETag/Last-Modified 条件请求，重复投递和重复任务合并；活跃来源最短 15 分钟轮询，无变化逐级降低到最长 24 小时。失败任务持久化重试，单任务最多 4 次，可在后台手动重试。相同来源不并发抓取。
- 任务领取使用 SQLite 写事务和租约标识，工作进程中断后 10 分钟可恢复，过期工作进程不能提交采集结果。
- TLS 校验域名，连接固定到已校验的公开 IP；逐次验证重定向；限制 HTTPS/端口、域名、超时、响应大小和 XML 声明。不读取登录内容，不抓取音频。

### 第二阶段：内容整理与审核

- 关键词规则与现有教练本地语义编码器共同识别预算、取舍、预留和风险主题，缺少本地模型时回退规则并记录原因。模型不会在网页请求期间下载。
- 使用精确 URL、来源内 GUID 排重；同作者、同标题、同日期且长简介高度一致时合并跨平台链接。仅主题相同不会合并，相似标题进入人工复核。
- 复用智谱密钥，生成结构化摘要、知识点、受众和难度建议。知识点必须含输入原文引证；输出格式或引证无效时回退可追溯摘录。所有输入都是公开标题与简介，不包含用户账单。
- 标明“仅基于发布者元数据，未审听完整音频”。生成摘要属于编辑建议，不能充当已验证事实。规则命中提示注入时跳过模型处理，并拦截自动发布。
- 原始内容哈希、处理版本、语义/AI 使用情况、回退原因、采集/发现/处理/审核时间、原始出处与审核行为可追溯。重要来源内容变化使审核失效；人工撤回不会被后续自动任务覆盖。编辑修正会使旧处理任务失效。

### 第三阶段：多源发现与推荐协同

- [Podcast Index 官方接口](https://podcastindex-org.github.io/docs-api/)：使用目录搜索与签名认证；配置 `PODCAST_INDEX_KEY` 和 `PODCAST_INDEX_SECRET`。
- [Listen Notes 官方接口](https://www.listennotes.com/api/docs/)：搜索中文节目并查询 RSS 元数据；配置 `PODCAST_LISTENNOTES_KEY`。使用真实服务端点，不使用返回假数据的 mock 服务。
- 默认每 6 小时按最多 3 个学习主题执行一次发现，每个主题最多处理 10 个结果。公开网页适配器仅提取页面声明的 RSS/Atom 链接；可接入运营者已获准使用的 RSSHub 订阅地址。
- 搜索得到的来源进入待确认队列，不自动成为可信来源或绕过抓取域名规则。目录密钥、订阅密钥不返回浏览器。
- [WebSub](https://www.w3.org/TR/websub/)：读取 RSS/Atom 的 hub 声明，向允许列表中的 hub 发起订阅，验证回调 topic/token、续租并校验 HMAC 签名。通知只触发原订阅源的条件读取，同一分钟重复通知合并；持续轮询保底。须部署公网 HTTPS 回调 `PODCAST_WEBSUB_CALLBACK_BASE`，核准 `PODCAST_WEBSUB_ALLOWED_HOSTS`。不支持 WebSub 的平台继续轮询；本版未实现 Podping 链监听。
- 已审核新单集拥有内容向量，进入现有冷却期/难度/主题/质量/反馈筛选，再交给 HSTU。HSTU 使用单集内容表示处理新 ID，不需要每新增一期就重新训练模型。模型或财务数据不足时返回明确的本地排序回退状态。
- 点击、曝光、收藏、不感兴趣和有帮助继续分别记录。点击不代表完整收听，未点击不自动记为负反馈。HSTU 的演示权重仍标记为演示，不能作为校园推荐效果证据。

## 启动

本地 `backend/run_dev_enhanced.py` 会启动同进程后台工作线程，默认 `PODCAST_LOCAL_WORKER_ENABLED=true`。新增配置须重启后端才能生效。

生产或仅运行普通 Flask 服务时，单独启动一个工作进程，使用同一环境配置与同一台机器上的持久化数据库：

```powershell
.\.venv\Scripts\python.exe backend/podcast_worker.py
```

执行一轮调度和任务处理后退出：

```powershell
.\.venv\Scripts\python.exe backend/podcast_worker.py --once --limit 100
```

`flask podcasts-sync` 和管理页“同步到期来源”只入队，独立工作进程负责执行。旧单集“同步 RSS”保留管理员显式同步兼容入口，同样使用受限的元数据读取与新单集入库流程。

## 新增接口

除 WebSub 签名回调外，下面接口都要求管理员认证，普通用户返回 403。

| 方法与路径（前缀 `/api/podcasts`） | 用途 |
| --- | --- |
| `GET /admin/pipeline` | 来源健康、目录与待审核数量、任务、候选来源、最近审计、外部服务配置状态 |
| `POST /admin/sources` | 幂等登记来源；`url/name/permission`，可选 `enabled/trusted/auto_approve` |
| `PUT /admin/sources/{id}` | 修改来源开关、信任及自动发布设置；地址不可原地替换 |
| `POST /admin/sources/{id}/sync` | 合并并入队采集，返回 202 与 `job_id` |
| `POST /admin/jobs/{id}/retry` | 为失败任务建立新的有界重试任务 |
| `POST /admin/discover` | `provider=podcastindex/listennotes`，入队目录发现 |
| `POST /admin/discoveries` | 提交 `url/title`，`kind=page` 时入队公开页面订阅发现 |
| `POST /admin/discoveries/{id}/review` | `accepted` 和 `permission` 确认接入或忽略 |
| `GET /websub/{source}/{token}` | 验证订阅意图，仅返回 `text/plain` challenge |
| `POST /websub/{source}/{token}` | 校验有效订阅与 HMAC，合并更新通知 |

## 验证口径

新增测试使用隔离数据库、合成订阅源和受控的外部响应，覆盖新单集增量更新、GUID 作用域、重复投递、条件请求、失败重试、租约恢复、内容修订、撤回、注入信号、回退、来源审核、WebSub 与学生请求无抓取等行为。另运行原有播客与 HSTU 回归和前端构建。

2026 年 10 月 15 日本地验证结果：

- 播客流水线、原有播客、HSTU 与财务推荐上下文测试共 **70 项通过**。
- 管理页、内容采集面板与每日推荐前端测试共 **8 项通过**。
- 前端生产构建通过，现有其他页面仍有未使用变量、旧链接可访问性等提示，本次新增页面无构建错误。
- 实际加载项目内已安装的语义编码器，对合成的校园预算简介识别出 `budget`、`buffer`，确认语义分支可运行；此检查关闭外部 AI 请求。

没有真实外部密钥、公网回调和已核准来源时，应说明服务尚未联调。生产验收需另测真实来源覆盖、发现到发布的各段延迟、摘要准确性、跨平台去重准确性及校园推荐效果，不填报虚构指标。
