# 青盈｜本月可用剩余卡片换算交互改进方案

日期：2026-10-28
状态：已完成第一版实施与针对性验证；实施和回退说明见《资金卡片换算改进实施说明.md》。

实施计划（2026-10-28）：保存原文件副本；逐步实现开关、资金时区、纯换算函数和独立展示层；仅首页启用；完成针对性测试、构建和回退说明。原文件副本位于 `tmp/funds-breakdown-20261028-before/`。

## 1. 改进范围

优化首页“今天 → 本月收支 → 本月可用剩余”的现有卡片。用户主动展开后，看见月余额如何均分到剩余每一天，并用钱币拆分动画辅助理解。

不新增页面、预算账户、提醒、奖励或消费决策弹层；不改变记账和储蓄规则。新增的日均数值只是现有余额的展示换算，不作为扣款限制、财务推荐输入或新的账务字段。

## 3. 展示与交互

默认保持原余额与资金口径，在金额旁增加原生按钮“查看每日均分”。金额文字本身保持可选择，按钮提供清楚的操作提示。

展开后的示例（示例日期为 2026-10-02）：

```text
本月可用剩余                       ¥4,386.00

¥4,386.00 ÷ 剩余30天（含今天）
接下来平均每天约                    ¥146.20

[钱币堆拆分，突出每天的一份]

按已记录的可用资金均分，未额外预留未来开支。
这是安排参考，不是今天还能花的金额。
                                  收起换算
```

- 月余额、天数、结果同时保留，不将 4386 直接滚动替换成 146。
- 结果文字展开即显示；动画不阻塞阅读或按钮操作。
- 首次主动展开时播放约 800 毫秒；同一次卡片挂载内不重复播放，收起后再展开只显示静态结果。
- 请求刷新、窗口聚焦及数据更新不触发动画。数据变化时立即更新文字、终止旧动画，保留静态画面。
- 不自动弹层、不播放声音、不提供随机金币奖励、不加入未经个人记录支持的餐饮类比。

## 4. 换算与有效性规则

资金来源唯一采用 `funds.available_remaining_month`：

```text
本月可用剩余
= 上月结转结余 + 本月实际收入 − 本月净支出 − 本月净储蓄划拨

剩余天数 = 资金快照所在月的总天数 − 快照当地日期的日号 + 1
日均参考 = 本月可用剩余 ÷ 剩余天数
```

不使用 `monthly_budget.remaining`、`monthly_cashflow.remaining`、预计收入或储蓄锁定总额替代余额，也不再次扣除锁定储蓄。未来开支本期只提示，不另做扣减。

计算前同时检查：

1. `available_complete === true` 且 `complete === true`。
2. 余额是有限 number，不能先把 null、空字符串或布尔值转成数字。
3. `as_of` 是带时区的有效 ISO 时间，`month` 与其在服务端时区下的月份一致。
4. 快照在该时区下仍属于今天；旧日、旧月或未来日期快照不参与换算。
5. 余额乘 100 并四舍五入后为安全整数；剩余天数为 1～31 的整数。

先检查数据完整性及时间有效性，再判断正、零、负余额；未确认的零值或负值同样不能作为确定结果展示。缺失或非法 `timezone`、无效 `now`、日期解析失败均返回不可计算状态，捕获格式化异常，不回退为设备时区。

内部以整数分计算：`amountCents = Math.round(amount * 100)`；非负金额的日均分值采用 `Math.floor(amountCents / remainingDays)`，向下保留到分，不高估均分金额。余数只是不进入展示值，不写回账务、不产生新的资金记录。金额统一固定两位小数。

| 情况 | 卡片行为 |
| --- | --- |
| 正数且有效 | 显示均分公式、日均参考与钱币示意 |
| 余额为零 | 显示“当前可用剩余为 ¥0.00”，不播放动画 |
| 余额小于零 | 显示“按已记录资金，本月可用资金不足 ¥X”，不做正向均分 |
| 有估算值但资金未确认 | 保留原金额及估算标识；不换算，提示“资金信息确认后可查看均分参考” |
| 资金来源失败或金额无效 | 不显示派生金额，沿用原加载/失败状态，支持现有重试 |
| 时间或月份无效、快照跨日 | 显示“正在更新资金参考”；刷新成功后计算，失败显示重试 |
| 金额大于零但日均不足一分 | 显示“平均每天不足 ¥0.01”，不显示成零余额 |

页面主标签使用“平均每天约”，不用“今天还能花”“每天只能花”或“已超支”。资金不足不必然等于超出预算。

## 5. 时间与数据刷新

现有 `_funds` 返回 `as_of`，但未透传快照的 IANA 时区。建议在原响应中增加 `timezone: snapshot['timezone']`，例如 `Asia/Shanghai`；这是同一快照的时间元数据，不新增业务接口。失败响应可以缺失该字段，此时不换算。

前端通过 `Intl.DateTimeFormat(..., { timeZone: funds.timezone }).formatToParts()` 获取快照及当前时刻的年月日；月天数按该年月计算。不要使用浏览器本地 `getDate()` 或把毫秒差除以 24 小时计算天数，以免设备时区和夏令时造成误差。

复用首页已有的 `transaction-saved`、`learning-saved` 和 `focus` 刷新机制。补充恢复可见时的日期检查，以及可见页面每 60 秒一次的轻量日期检查；只有快照当地日期发生变化才触发刷新。点击展开前也检查日期，避免定时器尚未执行时显示旧日均值。

跨日刷新期间立即隐藏旧换算结果，不把新日期与旧余额拼接。普通同日刷新可以保留标注“更新中”的既有快照；刷新失败后标注数据未更新，不将旧快照作为新结果播放。定时器和事件监听在卸载时清理，复用已有请求版本机制，防止旧账户或旧请求覆盖新结果。

自动日期刷新同一时刻只允许一个请求；同一过期快照每个当地日期最多自动尝试一次，失败后由现有重试按钮、再次聚焦或用户主动展开触发重试，避免定时检查持续重复请求。缺失或非法时间元数据自动重试一次后仍无效，显示“暂无法换算，请重试”，不无限显示加载中。

当前首页刷新失败会清空 `ledger`；本期沿用该行为并隐藏换算。同日刷新保留旧快照只适用于请求进行中的现有保留阶段，不新增失败后的余额缓存。

## 6. 组件与视觉实现

- `MonthlyAvailableFunds` 增加 `enableDailyBreakdown = false` 和必要的刷新状态、刷新回调参数；只有 `TodayHome` 显式打开。
- 新增 `src/utils/dailyFundsBreakdown.js`：纯函数，接收 `funds` 和可注入的 `now`，输出状态、剩余天数、原金额分值、日均分值及提示原因。计算与动画分离。
- 新增 `src/components/FundsBreakdownVisual.js`：只接收有效计算结果和播放状态，使用 SVG + CSS；不请求接口、不计算资金、不写入数据。
- 新增 `src/components/DailyFundsBreakdown.js`：管理展开、日期检查、刷新请求和动画生命周期，保持原资金卡片代码改动较小。
- `src/config/features.js` 提供首页接入开关，可通过 `REACT_APP_DAILY_FUNDS_BREAKDOWN=false` 并重新构建关闭增强。
- 新增局部样式，类名使用 `funds-breakdown-` 前缀，复用 `palette.css` 色板，不影响其他卡片。
- 不使用通用 `scene: reward/decision` 的奖励组件接口；当前需求只服务现有资金卡片。

钱币画面表达“从整堆取出一份”，最多绘制约 12 个 SVG 钱币元素，旁标“每天一份 × N 天，示意”。钱币数量不代表金额、不设置虚构面额，也不生成 30 组 DOM 钱堆。只动画 `transform` 和 `opacity`，不引入粒子或 3D 依赖。

按钮使用 `aria-expanded` 与唯一的 `aria-controls`；多实例 ID 使用 React `useId`。装饰 SVG 设置 `aria-hidden="true"`，读屏通过静态公式获取信息。展开区域不设强制高度，窄屏可换行，按钮保留键盘操作和可见焦点。

`prefers-reduced-motion: reduce` 下直接展示最终静态示意，不播放拆分或数字滚动；不把动画帧写入读屏实时区域。收起、数据变更和卸载都中止动画，并清理可能存在的结束监听或计时器。

1. 给现有资金响应透传快照时区，完成纯换算函数与边界验证。

4. 执行相关验证并人工检查移动端排版、键盘操作和静态降级。

必要验收用例：

| 输入或操作 | 预期 |
| --- | --- |
| 2026-10-02，¥4,386.00 | 剩余30天，¥146.20/天 |
| 2026-10-28，¥4,386.00 | 剩余4天，¥1,096.50/天 |
| 2026-10-31，¥4,386.00 | 剩余1天，¥4,386.00/天 |
| 2028-02-28 / 2027-02-28 | 分别剩余2天 / 1天 |
| ¥100.00，剩余3天 | ¥33.33/天；不写回余下的一分 |
| ¥0.01，剩余4天 | 显示每天不足一分 |
| null、字符串、NaN、Infinity、未确认估算值 | 无日均数值，无动画 |
| 零余额、负余额 | 分别显示零余额、资金不足，不生成正向金币 |
| 设备时区不同、个人时区有夏令时 | 依据服务端时区的日历日期计算 |
| 跨日、跨月、后台恢复、展开前已过期 | 先失效旧换算，再刷新资金 |
| 连续展开、收起、同日刷新、切换账户 | 动画不因刷新重复播放，无旧数据覆盖 |
| 开启减少动态效果 | 结果立即可读，无拆分动画 |
| 账本使用同一资金卡片 | 默认无换算入口，结转确认行为保持正常 |

已扩展 `MonthlyAvailableFunds.test.js`、`TodayHome.test.js`，新增纯函数及展示层的日期、金额、动画和刷新用例；后端补充原资金响应时区与快照一致性断言。相关验证及构建结果记录在实施说明中。
