# 青盈：理财思考与实践

## 本次功能

登录后进入“理财成长”（`/#/learning`），按以下路径使用：

1. 在“我的资料”填写生活费或月收入、到账日，选择学习主题；可记录自己的消费规则和未来开支。
2. 完成八题习惯自我探索。结果仅用于选择练习主题，不是专业量表、财务健康诊断或投资风险评级。旧版结果保留，但不混入新版趋势。
3. 在“七天练习”完成七次情境思考。可以跳过、重做或按自己的节奏完成。练习覆盖安排收支、理解取舍、留有余地、理解风险。
4. 在“消费选择”比较购买、等待与调整预算，记录需要和理由。保存选择不会自动记账，实际发生后到个人中心记账。
5. 手动或语音记账时，可选记录消费计划与当时需要；之后可回访“符合／部分符合／不符合预期”。历史后悔字段保留，但新回访不使用二元后悔评分。
6. 在“每周复盘”回看事实、反馈上次行动、制定下次行动并写下自己的原则。无消费也能复盘。
7. “我的成长”展示实践记录、主题覆盖和原则。记账、练习、选择及复盘均可计入参与日期，次数不作为能力认证。

未来开支仅在站内提醒，标记处理不会自动记账。不设置邮件、推送或后台通知。

## 行为经济学依据与边界

- 当下偏好：提供延后考虑和自主比较，不凭单次消费给用户贴标签。
- 有限注意力：在选择与复盘页面显示用户记录的具体未来开支。
- 心理账户：练习同时看待生活费、红包和退款，避免只看单项预算。
- 自我承诺：允许用户自定可修改的行动规则，不锁定资金、不惩罚中断。
- 金融教育：情境、概念、表达理由、行动与复盘相连接。

参考研究：

- Ericson & Laibson, *Intertemporal Choice*: https://www.nber.org/papers/w25358
- Karlan et al., *Getting to the Top of Mind*: https://www.nber.org/papers/w16205
- Thaler, *Mental Accounting Matters*: https://www.anderson.ucla.edu/faculty_pages/keith.chen/negot.%20papers/Thaler_MentalAccounting99.pdf
- Beshears et al., *Self Control and Commitment*: https://www.nber.org/papers/w21474
- Kaiser et al., *Financial Education Affects Financial Knowledge and Downstream Behaviors*: https://www.nber.org/papers/w27057

研究支持机制和教育方向，不证明青盈的具体界面或七次练习已经有效。没有宣称通过打卡、自评分数或省钱金额验证教育成效。

## 计算和数据

- 收入读取账号资料；没有填写时不使用 2000 元默认值。零收入允许保存。
- 报告标注记录区间、条数和估算限制。输入不完整时不会假装知道完整的可支配余额。
- 单次购买按一次性支出估算目标影响，不将它误当成每月重复支出。假设与结果一起展示。
- 未来开支不会自动从试算中扣除；页面提醒用户另行考虑。
- 新资料、练习、选择、回访和复盘存入 `learning_entries`，按用户隔离；练习按题目更新，复盘按北京时间周一为起点更新。
- MySQL 增加 `learning_entries` 表和 `transactions.planned/purpose` 字段。启动时运行非破坏性迁移；需要建表和 ALTER 权限。启动失败会明确报错。
- Firestore 使用既有用户集合路径。开发内存模式按项目原有本地 JSON 方式保存，改为原子写入。
- 开发模式认证绕过仍为单个测试用户，不能用于多用户部署。正式账号隔离依赖 Firebase 验证后的 UID。
- AI 对话默认只发送本次输入和会话历史；勾选引用记录后，才发送账号资料和最近五条学习记录。规则禁止把记录里的文字当成系统指令。

## 验证与后续试用

本地检查：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q -p no:cacheprovider
$env:CI='true'
npm.cmd test -- --watchAll=false --runInBand
npm.cmd run build
```

自动化覆盖核心数值计算、新增 HTTP 流程、非法输入、身份隔离、存储失败、资料保存、无消费复盘和前端失败重试。MySQL/Firestore 适配器有模拟契约测试，正式部署前仍需连接目标数据库做迁移与读写验收。

后续试用建议：先邀请 5–10 位自愿参与者完成一个周期，核对是否理解提示、是否感到压力、是否能把概念用于新情境。小样本用于发现问题，不能据此证明因果效果。

若开展效果研究，先确定同难度的前后情境题和评价标准，再在充分知情同意下比较普通记账与新增引导。主要观察预算信息识别、解释取舍、识别风险与提出备用方案的能力；留存、点击、参与次数是过程指标。记录压力与负担作为平衡指标。当前版本不暗中分组、不自动上传研究数据。
