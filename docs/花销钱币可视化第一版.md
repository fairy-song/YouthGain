# 花销钱币可视化｜第一版实施计划

日期：2026-10-28。

实施完成：2026-10-29。状态：已接入现有账本，完成针对性测试与桌面/手机视觉检查。

目标：把已发生的支出展示成对应的钱币与纸钞，强化金额感。本次改进记账成功反馈与已有账单的金额回看，不再以“余额均分”为主。

实施顺序：

1. 备份本次涉及的文件，新增独立开关；保留现有每日均分与播客改动。
2. 使用人民币真实面额拆分整数分金额：100/50/20/10/5元用纸钞示意，1元、5角、1角、5分、1分用硬币示意。总额准确，重复面额以叠放和数量表示，限制实际绘制数量。
3. 手动与账本语音记账确认保存后展示支出钱币及一次移出动效，不等待机会成本接口；保存失败、收入、退款和转账不触发。
4. 现有账单的支出金额改为可展开按钮，在原表格中回看面额构成。历史回看静态展示；退款关联支出明确展示原支付金额，不冒充净支出。
5. 验证精确拆分、异常金额、保存成功/失败、迟到请求、收入与退款隔离、键盘操作和减少动态效果；执行构建和浏览器视觉检查。

回退：通过 `REACT_APP_SPENDING_MONEY_VISUAL=false` 并重启开发前端/重新构建关闭；完整代码回退使用本次备份清单，不恢复整库，不影响其他改进。

## 已完成的第一版

- 手动支出确认保存后立即展示钱币，不等待机会成本接口；原有机会成本反馈保留。
- 账本语音录入保存后，先关闭弹窗再通知父页面展示，保证移出动画不被弹窗遮挡；计时器在重置和卸载时清理。
- 最近账单中的支出金额可点击展开/收起，支持键盘及展开状态说明。收入、退款、本人转账不生成支出钱币。
- 关联退款的原支出显示“这笔原支付”，并标明已退金额，避免把原支付误认为当前净支出。
- 同一面额最多绘制3层，实际数量始终用文字标注。大额不会生成成千上万的图形；金额以分计算并保证面额合计相等。
- 首次保存播放约1.4秒的钱币移出及淡化动效，面额和数量保持可读；历史回看静态展示。系统减少动态效果时不播放。
- 仅使用 React、SVG 与 CSS，未引入依赖、修改后台接口或写入任何演示/真实账目。
