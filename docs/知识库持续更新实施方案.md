## 第一版已实现

- 后台“知识库管理”顶部提供来源启停、新增来源、立即检查、失败提示、版本正文对比、审核发布、拒绝、撤回及恢复旧版。
- 5个预置来源模板默认停用：管理员核对来源后启用，启用后每日检查、启动补查；未启用不会访问外部网站。
- 仅支持公共HTTPS正文网页与HTML文章目录，无新增依赖。目录每次最多检查5篇并轮换游标；动态渲染、验证码、PDF、RSS和API专用适配器留待后续接入，不声称首版覆盖全部来源格式。
- 复用播客安全网络请求：主机白名单、公共IP验证、TLS主机校验、逐跳验证、响应体和超时限制；正文标准化后生成SHA-256指纹，条件请求仅用于正文页面。
- 来源错误会保留旧内容并退避重试；检查租约防止并发重复请求。版本正文不可原地修改，发布记录追加保存；审核带当前版本校验，避免过期页面覆盖新发布。
- 采集版本默认待审核；管理员明确核验原文、日期、地区和使用范围后才能发布。第一版是原文审核发布，不自动生成AI摘要；若需自行撰写摘要，请使用原有手动文章入口并注明来源。
- 已审核内容与原文章合并读取，教练最多取2000篇；境外来源首版仅在知识列表展示，不进入内地教练检索。超出2000篇后仍需进一步分页/索引服务改造。
- 原有语义检索按内容指纹重建索引目录，新加片段向量缓存只编码变化文本；进程重启后首次重建，缓存非跨进程持久化。回答依据透传来源链接、地区、版本和采集日期。
- 来源停用表示停止采集；如需停止回答引用，使用版本“撤回发布”。

## 运行

本地增强启动器已有播客工作进程，新增知识检查独立捕获错误，不会因知识失败中断播客任务。独立运行或服务器部署可以使用：

```powershell
.venv/Scripts/python.exe backend/knowledge_worker.py
# 仅补查一次
.venv/Scripts/python.exe backend/knowledge_worker.py --once
```

服务必须持续运行才能自动更新；关机期间不更新，重启后处理到期来源。首版默认不额外注册系统计划任务。数据在现有播客库旁的 `knowledge_updates.db`，也可在应用配置中设置 `KNOWLEDGE_UPDATES_DB_PATH`。单机SQLite适用当前部署，不宣称支持多服务器分布式调度。

## 验证与回退

最终通过50项后端测试（含播客流水线回归）、5项前端相关测试与生产构建；测试使用合成网页，不对外站真实采集成功率作保证。某些官方站点依赖JavaScript，无法提取时明确显示失败，需要后续适配，绝不把导航或验证页面当文章自动发布。构建输出位于 `tmp/knowledge-updates-build/`，未覆盖原发布目录；运行中的旧后台需重启才能加载新增接口与任务。

在隔离副本中已演练完整代码回退，验证原文件恢复及后续编辑保护。首版后台版本台账最多显示最近300条，优先适用于当前小规模试运行，后续扩展需分页；这不是数据库容量上限。

新增数据台账与原24篇内容隔离，无用户资料改写。备份位于 `tmp/knowledge-updates-20261029-before/`。预览代码回退：

```powershell
.venv/Scripts/python.exe scripts/rollback_knowledge_updates.py
```

加 `--apply` 执行完整代码恢复，先验证清单与后续修改并归档当前文件。仅回退本次源码；台账和用户数据不删除，以便审计或恢复。回退后重启后台、重启开发前端或重新构建。

快速停止自动检查及动态内容接入，可在应用配置中设 `KNOWLEDGE_UPDATES_ENABLED=False`（布尔值）；这不是已经接通的环境变量。或者在后台逐个停用来源，并单独撤回不再采用的发布版本。
